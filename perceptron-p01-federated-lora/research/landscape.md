## 1. The problem in one paragraph
Each device k holds data D_k and fine-tunes a LoRA adapter ΔW_k = B_k A_k on a frozen base model. The server must produce one shared adapter. Four things break naive FedAvg here: (i) averaging A and B separately gives mean(B)·mean(A) ≠ mean(B·A) ("aggregation noise"); (ii) devices of different power want different ranks r_k; (iii) devices do different numbers of local steps, and some drop out mid-round; (iv) weights ∝ n_k let a data-rich device set the direction of the shared model. The literature splits along exactly these lines.

## 5. Benchmarks and frameworks
- **FedLLM-Bench** ([2406.04845](https://arxiv.org/abs/2406.04845)): "previous works all rely on arti[ficial]" partitions, so it offers realistic federated LLM datasets (abs). It is a target for the finals evaluation.
- **Flower** ([2007.14390](https://arxiv.org/abs/2007.14390), the framework paper). `flwr` 1.39.0 is installed: Message API with `ServerApp`/`ClientApp`/`Grid`/`ArrayRecord`, read from the installed source. - **FlowerTune LLM leaderboard** (details in [`raw/frameworks_benchmarks.md`](raw/frameworks_benchmarks.md), agent-verified):
  - Four challenges (General NLP, Finance, Medical, Code). The baseline is Mistral-7B + LoRA + FedAvg; the lead confirmed the Mistral-7B baseline and the `flwr new @flwrlabs/flowertune-llm-finance` starter in the [README](https://github.com/adap/flower/tree/main/benchmarks/flowertune-llm).
  - **Finance** trains on `flwrlabs/fingpt-sentiment-train`; the lead confirmed via the HF API that it is MIT-licensed with 76,772 training examples. Data is split IID across 50 clients, and evaluation is accuracy on FPB / FiQA / TFNS.
  - Per the agent, the baseline averages 45.27 and a SmolLM2-1.7B-Instruct entry reaches 67.90. Both figures are agent-read, not re-checked by the lead.
  - **This is our finals benchmark.** It is Optiver-relevant, public and accuracy-scored. We add our heterogeneity (Dirichlet non-IID splits, device budgets, dropouts) and run 0.5B–1.7B models, so we can compare directly against the leaderboard's IID FedAvg setting.
- **FedScale** ([2105.11367](https://arxiv.org/abs/2105.11367), ICML 2022): system-performance benchmark with device behaviour (title). It is the source for realistic availability traces in the next iteration.
- PEFT 0.21.2 and torch 2.10 (MPS) run our skeleton today; PyPI also lists torch 2.14.1 and mlx-lm 0.32.0 (seen 2026-10-04).

**What this means for our design.**
- Production federated PEFT (NVIDIA FLARE, FlowerTune) aggregates LoRA with **plain FedAvg**, which is exactly the inexact, n_k-weighted baseline our pilot shows harming small domains.
- Apple ships adapters but trains them **off-device**.
- Google's production cross-device FL is the reference for scale and privacy (DP-FTRL, clipping, participation criteria); our system does not add DP yet.
- Decentralised-training networks (Templar, Prime Intellect) **score or validate each contributor**. That is the closest industry practice to our per-device influence audit. Ours is cheaper (one inner product per device per round, exact because the anchor space is linear), and we pair it with a leave-one-out ground truth.

## 7. Implications for the design
1. Baselines must include FedAvg over A and B (homogeneous and heterogeneous rank), FFA-LoRA-style frozen A without our extras (`anchor_naive`), and, for the finals, FedEx-LoRA or FLoRA and RoLoRA (exact or alternating, trainable A).
2. Frozen A, step normalisation, memory and uniform weights are each published. The defensible contribution is the **integration + measurement**: exact heterogeneous-rank aggregation as the substrate that makes FedNova/MIFA/macro weights *exact* for LoRA, plus a dominance audit. Claim only that.
3. RoLoRA argues frozen A limits expressiveness. Test it directly: anchor vs trainable-A baselines at equal communication.
4. Use FedLLM-Bench or FlowerTune datasets for the finals once the network allows; the local-text domains are the overnight proxy.
