# Frameworks and benchmarks for federated LoRA

Access date for every source: 2026-10-04. Primary sources only: official docs, GitHub, PyPI/HF APIs/cards, and arXiv. `UNVERIFIED` means I opened sources but did not find confirmation.

## Executive summary

- **Recommended finals dataset/metric:** use the FlowerTune **Finance** task, but scale down to **SmolLM2-135M + LoRA** on `flwrlabs/fingpt-sentiment-train`; report mean **accuracy over FPB/FiQA/TFNS**. It matches Optiver/finance judging, has clear public labels, and fits an M5 better than 7B baselines.
- Finance is the most relevant track: training set is `flwrlabs/fingpt-sentiment-train` (76,772 train examples, MIT), split by Flower into **50 IID clients**; evaluation is FPB, FiQA, TFNS accuracy.
- FlowerTune baseline config is heavy: Mistral-7B-v0.3, 4-bit, LoRA `r=32`, alpha 64, seq len 512, batch 16, 3 epochs, max 10 steps/client, 200 rounds; Finance baseline average is **45.27%**.
- The live Finance leaderboard snapshot showed **ZeroOne.AI/Qwen2.5-7B** at 84.58 mean, then Qwen2.5-7B entries at 75.51/74.95; the page exposed base model and comm cost, not detailed methods, so techniques beyond model choice are **UNVERIFIED**.
- Flower 1.39-style apps use `ServerApp`, `ClientApp`, `Message`, `RecordDict`, and strategy classes such as `FedAvg`, `FedProx`, `FedAdam`, `FedYogi`, `FedAvgM`, `FedMedian`, `FedTrimmedAvg`, `Krum`, `MultiKrum`, `Bulyan`, and DP wrappers.
- For non-IID simulation, prefer `flwr_datasets.partitioner.DirichletPartitioner(num_partitions, partition_by, alpha, min_partition_size=10, self_balancing=False, shuffle=True, seed=42)`; common FL papers use alpha values, but FlowerTune Finance itself is IID.
- PEFT 0.21 LoRA options include rsLoRA, DoRA, PiSSA/OLoRA/EVA/LoftQ/CorDA/LoRA-GA/MiCA init paths, `target_modules="all-linear"`, and Llama/Mistral defaults `q_proj,v_proj`.
- Device availability can be simulated from FedScale traces (`client_device_capacity`, `client_behave_trace`); no direct Flower adapter was confirmed.

## FlowerTune LLM leaderboard

FlowerTune LLM has four challenges: General NLP, Finance, Medical, Code. Starter apps are generated by `flwr new @flwrlabs/flowertune-llm-{general-nlp,finance,medical,code}` and use federated instruction tuning with Mistral-7B, LoRA/PEFT, Flower Datasets, and FedAvg. Static dataset config and the required SuperNode count cannot be changed for eligible leaderboard submissions. Baseline results are ranked by track average.

| Track | Training HF ID | Clients / partition | Eval datasets | Metric | Baseline avg |
|---|---|---:|---|---|---:|
| General NLP | `flwrlabs/alpaca-gpt4` | 20 IID; 10%/round; 200 rounds | MMLU STEM, Social Sciences, Humanities | accuracy | 12.82 |
| Finance | `flwrlabs/fingpt-sentiment-train` | 50 IID; 10%/round; 200 rounds | FPB, FIQA, TFNS | accuracy | 45.27 |
| Medical | `flwrlabs/medical-meadow-medical-flashcards` | 20 IID; 10%/round; 200 rounds | PubMedQA, MedMCQA, MedQA, CareQA | accuracy | 32.82 |
| Code | `flwrlabs/code-alpaca-20k` | 10 IID; 20%/round; 200 rounds | MBPP, HumanEval, MultiPL-E JS/C++ | pass@1 | 27.36 |

Finance details: evaluator loads `takala/financial_phrasebank` config `sentences_50agree`, `pauri32/fiqa-2018`, and `zeroshot/twitter-financial-news-sentiment` validation split; maps answers to negative/neutral/positive and uses sklearn `accuracy_score`. Baseline per-dataset results are FPB 44.55, FIQA 62.50, TFNS 28.77, average 45.27. Live Finance snapshot: ZeroOne.AI/Qwen2.5-7B scored 84.58 mean with 30.1 GB communication; two FL-finetune-JB-DC/Qwen2.5-7B entries scored 75.51 and 74.95 with 3.8 GB; SmolLM2-1.7B-Instruct scored 67.90 with 10.7 GB; baseline Mistral-7B used 101.6 GB. FAQ: 13B base-model ceiling and 200 GB communication limit.

## Flower API and runtime

Confirmed names: `flwr.serverapp.ServerApp`, `flwr.clientapp.ClientApp`, `flwr.app.Message`, `flwr.app.Metadata`, `flwr.app.RecordDict`, `ArrayRecord`, `ConfigRecord`, `MetricRecord`, and `Grid`. In the Finance app, `@app.main()` launches a strategy on a `Grid`; `@app.train()` receives a `Message`, trains on one partition, and returns a reply `Message`. `Message` carries content records and metadata such as message type, destination node, group/round, TTL, and reply linkage.

Strategy docs list `Strategy`, `FedAvg`, `FedAvgM`, `FedProx`, `FedAdagrad`, `FedAdam`, `FedYogi`, `FedMedian`, `FedTrimmedAvg`, `Krum`, `MultiKrum`, `Bulyan`, `QFedAvg`, `FedXgbBagging`, `FedXgbCyclic`, plus DP wrappers `DifferentialPrivacyClientSide{Fixed,Adaptive}Clipping` and `DifferentialPrivacyServerSide{Fixed,Adaptive}Clipping`. Client mods list `fixedclipping_mod`, `adaptiveclipping_mod`, `LocalDpMod`, `secagg_mod`, and `secaggplus_mod`.

Simulation uses the same `ClientApp` logic as deployment; Flower docs describe a Simulation Runtime with Ray as default backend, resource settings for CPU/GPU, ephemeral client materialization, and local `flwr run` via managed SuperLink. Deployment uses long-running SuperLink, SuperNodes, and SuperExec processes for ServerApp/ClientApp execution.

## PEFT 0.21 LoRA options

`LoraConfig` confirms `r`, `target_modules`, `exclude_modules`, `lora_alpha`, `lora_dropout`, `bias`, `modules_to_save`, `rank_pattern`, `alpha_pattern`, `layers_to_transform`, `layers_pattern`, `trainable_token_indices`, `target_parameters`, `layer_replication`, `use_rslora`, `use_dora`, `use_qalora`, `alora_invocation_tokens`, and `lora_bias`. Init options include default Kaiming-A/zero-B, `gaussian`, `pissa`, `pissa_niter_N`, `olora`, `eva`, `loftq`, `corda`, `orthogonal`, `mica`, and `lora_ga`; docs describe LoRA-GA requiring full-precision weights and not supporting quantized models. MiCA sets A=0 and freezes B; I found no generic “freeze A” option, so freeze-A is UNVERIFIED. PEFT constants map Llama/Llama4/Mistral/Qwen2/Qwen3 to default `q_proj`,`v_proj`; `target_modules="all-linear"` targets all linear/Conv1D except output for QLoRA-style training.

## Device-availability traces

Flower docs mention simulating client availability but no packaged trace dataset was confirmed. FedScale’s primary repo documents pickle traces: `client_device_capacity` for compute/communication and `client_behave_trace` keyed by client id with duration, active/inactive intervals, finish time, and device model. A direct FedScale-to-Flower adapter is UNVERIFIED.
