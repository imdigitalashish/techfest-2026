# Independent code and evaluation review — 4 Oct 2026

Scope: `origin/main` at `2d3bf42`; implementation, CPU contract checks, committed `v1` evidence, and the planned `v2` queue. No model training or MPS run. Paper checks used [FFA-LoRA §4, Eq. (4)](https://arxiv.org/html/2403.12313#S4.E4) and [FlexLoRA §3.2 / Appendix B](https://arxiv.org/html/2402.11505#S3.SS2), opened on 4 Oct 2026.

## Five-line verdict
- **Core maths:** Frozen shared A makes the stated mixed-rank delta aggregation exact; the FFA-LoRA and FlexLoRA aggregation equations are implemented faithfully.
- **Headline evidence:** The three-seed `v1` macro advantage is promising, but no committed five-seed `v2` results existed at this revision; do not promote the pilot CI to a final claim.
- **Device feasibility:** A rank-2 client still holds and runs a rank-16 PEFT adapter, so the current simulation does not demonstrate rank-2 memory/compute feasibility.
- **Comparison:** The seeded availability schedule is paired, but Anchor accepts 46 cut-off client-rounds across seeds 0–4 that the baselines discard, on top of changing ranks, weights, and memory.
- **Trade-off:** In `v1` dropout, Anchor beats the starter on macro loss but loses on micro loss (+0.1121 nats/token, paired 95% CI [+0.0974, +0.1268]); dominance and dropout stability need narrower claims.

## Issues

1. **BLOCKING — The weak-device rank budget is not an actual resource budget.** `components/local_trainer/trainer.py:44-52,85-108`; `components/aggregator/strategies.py:170-177`. One PEFT model is built with `r_max=16` for every device; masking gradients does not shrink the forward pass, B's gradient/AdamW state, or A/B storage. `Anchor.client_view` even retains nonzero high-rank columns on a rank-2 client after the rank-16 client's first update (CPU toy check: rank-1 view had high-column absolute sum 6, not zero). This differs from FlexLoRA's truncated local view and invalidates the claim that the simulated phone/Pi *fits* its assigned rank. **Fix/experiment:** instantiate and benchmark actual rank-`r_k` local adapters (and specify how the higher-rank global residual is handled); record peak RAM/FLOPs/tokens per second. Until then, claim only a reduction in logical upload size, not weak-device memory or compute.

2. **BLOCKING — The head-to-head cannot attribute its gain to the proposed aggregation without matched-work controls.** `components/orchestrator/simulate.py:74-97`; `components/device_simulator/profiles.py:18-28`; `components/aggregator/strategies.py:329-355`. The *allowed-step schedule* is identical for a seed, but the baselines discard every cut-off client before training, while `anchor_full` trains and accepts it; across seeds 0–4 that is **46 extra partial client-rounds** for Anchor, versus none for the baselines. It also replays missing clients, changes `n_k` to uniform weights, clips and normalizes updates, and gives always-online c0 rank 16 versus the homogeneous baselines' rank 8. Accepting partial work is a legitimate component of the proposed method, **not cheating**, but the full-package macro comparison cannot identify which component helps. **Fix/experiment:** run paired `anchor_full` with partial acceptance disabled, baseline variants accepting the same partial work, a device-rank-matched frozen-A control, and one-at-a-time uniform-weight/memory/clip controls. Rotate domain, data volume, rank, and forced outage across devices (including c0); report actual steps, FLOPs, bytes, and completed-work counts beside loss.

3. **BLOCKING — Five-seed evidence is not yet auditable and the runner will silently mix or double-count incompatible runs.** `eval/run_matrix.py:35-49,60-87`; `eval/queue_runner.py:45-54`; `eval/summarize.py:66-83,93-106,182-185`. There are **zero tracked `v2_*.jsonl` files** at the reviewed revision; the pilot `v1` rows carry different `env.commit` values (`e6b17ac`, `e74395d`, `30f90cb`) and no code hash. Both resume paths treat `(strategy, seed, rounds)` as sufficient even if code, model, dataset, or config changed. The summarizer prints every distinct code hash but neither rejects mixed hashes/dirty runs nor duplicate or missing seeds; `paired()` counts duplicate rows from one seed as independent observations. `dirty` checks `components/` and `eval/run_matrix.py`, not the other eval scripts or data inputs. **Fix/experiment:** before any `v2` CI or canonical number, enforce exactly one row per expected scenario/strategy/seed, identical training-code/config/data manifests (and a justified policy for unrelated commits), non-dirty provenance, five shared seeds for headline strategies, and committed per-round logs. Abort rather than pool mismatches; hash token blocks, tokenizer/model revisions, and source manifests as well as code. The new `eval/summarize.py` edit itself changes `code_sha` if the queue spans that edit, even though training logic did not change: inspect the actual hashes rather than assuming the queue's label guarantees one revision.

4. **MAJOR — The homogeneous published baseline is not a literal rank-8 PEFT run at the stated alpha, and its optimizer is untuned.** `components/local_trainer/trainer.py:44-52,80-108`; `components/orchestrator/simulate.py:30-33`; `components/aggregator/strategies.py:329-333`. FFA-LoRA correctly freezes shared A and averages B as in [§4, Eq. (4)](https://arxiv.org/html/2403.12313#S4.E4); Kaiming initialization is also considered in [Appendix A.8](https://arxiv.org/html/2403.12313#A1.SS8). But both `ffa_lora` and the starter are masked rank-8 slices of a PEFT **rank-16** module: `alpha=32` therefore gives scale 32/16=2, whereas a separate PEFT rank-8, alpha-32 module gives scale 4. They also use the same fixed AdamW learning rate despite FFA-LoRA's [§5.1](https://arxiv.org/html/2403.12313#S5.SS1) tuning different learning rates with SGD. The direction of any advantage is **unknown**, not evidence that FFA-LoRA is intrinsically worse. **Fix/experiment:** add genuine rank-8 PEFT baselines with explicit, matched effective scaling and modest equal-budget LR sweeps; disclose optimizer and scale as deviations from the paper's experiments.

5. **MAJOR — FlexLoRA diagnostics describe an unserved full product, not necessarily the evaluated adapter.** `components/aggregator/strategies.py:302-324`; `eval/summarize.py:100-122`. The `n_k`-weighted product average and SVD redistribution match [FlexLoRA §3.2 and Appendix B, Algorithm 2](https://arxiv.org/html/2402.11505#A2): using B·A units is valid because the PEFT scale is common to clients. However, `product_space_report` uses the full `g["W"]`, while evaluation uses only its rank-16 SVD truncation; the summary records but does not display the resulting `truncation_error`. A CPU rank-2 toy with a rank-4 pooled product gave **70.7% discarded Frobenius norm but `aggregation_error=0`**. This is a reporting/serving choice, not an error in the paper's SVD equation. **Fix/experiment:** show the tail error in the headline table and distinguish full-product exactness/influence from the *served* rank-`r_max` product's residual and influence; state the serving-rank budget and, if useful, evaluate an untruncated reference at its actual memory cost.

6. **MAJOR — The relative aggregation-error metric can falsely say “exact.”** `components/aggregator/strategies.py:43-63`. The code returns zero when `||sum(c_k)||=0`, even if the applied update `P` is nonzero. CPU counterexample for FedAvgAB from zero B: equal-weight clients `(A_1,B_1)=(1,1)`, `(A_2,B_2)=(2,-0.5)` have canceling product contributions, but averaged factors give `P=0.375`; the report says `aggregation_error=0.0`. Near-zero denominators are also ill-conditioned. **Fix/experiment:** always report absolute residual `||P-sum(c_k)||`; represent undefined/unstable relative error explicitly instead of zero, and add this cancellation test. Do not interpret a reported zero as proof of exactness without the denominator.

7. **MAJOR — Equal weights and the current clipping rule do not enforce “no dominance.”** `components/aggregator/strategies.py:32-63,193-226`; `components/orchestrator/simulate.py:112-130`. `s_k=<c_k,P>/||P||^2` is a valid *projection*, not a probability or a causal improvement; it blows up under cancellation, and only sums to one for an exact nonzero applied update. `||c_k||/sum_j||c_j||` is bounded but measures vector magnitude, not benefit to a device/domain. The 2×-median clip uses the **upper** median with two reporters and the B-direction norm, before adding remembered directions; in a CPU two-reporter case with uniform weights and updates 100 versus 1, c0 still has projection and norm shares **0.9901**, without clipping. Un-decayed remembered directions may also be replayed for four rounds after their original clipping. **Fix/experiment:** report effective reporter count, `||P||`, weights, both shares, age and norm of memory; clip/evaluate in product space including replay if a per-round norm cap is intended. Use leave-one-device-out domain loss and a Sybil/rotated-outage test for the causal fairness claim. The new summary correctly exposes the macro-versus-micro trade-off; do not replace that trade-off with a single “dominance” number.

8. **MAJOR — The non-Wiki holdout is path-disjoint, not content-disjoint or reproducible from the pinned packages alone.** `components/data_partitioner/local_domains.py:30-32,39-84,92-119`; `scripts/fetch_data.sh:5-11`. WikiText uses train versus test (good); other domains hash the **absolute path**, not the file contents, to select eval files. The same text in a second path or domain can still occur in both splits; I found no demonstrated leak, but there is no content-overlap check. Moving the venv changes path hashes and potentially which documents are evaluated; `/usr/share/man` varies by host. The script fetches the latest WikiText snapshot, `_wiki_docs` selects the lexicographically last cached snapshot, the model revision is unspecified, and `.data/` caches are keyed only by names and block counts. Each eval domain uses just 48 contiguous blocks × 128 tokens = **6,144 tokens**, potentially from few correlated documents. **Fix/experiment:** freeze and record a content-hashed train/eval file manifest, dataset and model/tokenizer revisions, and token-block digests; deduplicate at document/content level across splits/domains, invalidate caches on source changes, and add a larger document-level holdout or document-bootstrap uncertainty. Seed CIs alone quantify neither test-corpus nor host variation.

9. **MAJOR — The new paired CI calculation is right, but “every domain improves” is still a multiple-comparison claim.** `eval/summarize.py:48-53,66-68,123-171`. The two-sided t formula and pairing by seed are correct *if* seeds are unique, independent runs with comparable code/data; the new summary now reports each domain and each baseline. It does not adjust for five domains, multiple baselines/metrics, or ratchet selection. For the `v1` three-seed Anchor pilot, the cheaders gain over untuned is +0.00689 with marginal 95% CI [+0.00257, +0.01120], but its **five-domain Bonferroni simultaneous 95% CI is [-0.00307, +0.01684]**. Five seeds give only four t degrees of freedom; even five same-sign gains cannot pass a two-sided 5% sign test (smallest p=0.0625). With the pilot paired macro SD 0.01138, about **8 seeds** would give an unadjusted ±0.01 CI half-width, or **13** would give ~80% power for a 0.01 effect at two-sided 5%, assuming that SD persists; smaller effects need more. **Fix/experiment:** prespecify the primary macro comparison, use simultaneous/Holm-adjusted per-domain intervals for “every domain,” provide effect/precision-based seed planning and independent holdout evaluation; label unadjusted pilot intervals exploratory.

10. **MAJOR — Flower's MPS aggregation path mixes CPU and MPS tensors.** `components/flower_adapter/serialization.py:23-25,51-59`; `components/flower_adapter/server_app.py:100-106,146`; `components/aggregator/strategies.py:70-80,180-190,244-245`. Flower `ArrayRecord` payloads are converted to CPU, while the initialized Anchor global B is on the selected MPS device. `_pad` returns a full-rank c0 payload unchanged on **CPU**, but pads a smaller-rank payload onto the reference **MPS** device; their sum and the MPS global update cannot be added. The FedAvgAB full-shape `_pad_pair` has the same device inconsistency. A CPU/meta-device shape check confirms full-width returns on CPU while sliced returns on the reference device; I did **not** run MPS training. **Fix/experiment:** normalize payload dtype/device to the global reference on *both* padding paths, then run a small real MPS Flower-versus-in-process parity check in an unloaded environment.

11. **MAJOR — The claimed seed-only anchor transport is not the Flower transport being measured.** `components/aggregator/strategies.py:170-177`; `components/flower_adapter/server_app.py:70-92`; `components/flower_adapter/serialization.py:17-26`; `components/orchestrator/simulate.py:91-94,134`. Each Flower round serializes and downloads **full-rank A and B** to every client (including rank-2 clients), rather than regenerating A from a seed. `upload_mb` is `4 * payload.numel()` only: correct for the fp32 *logical uplink*, but it omits these downlinks and Flower record/metadata overhead. **Fix/experiment:** either implement seed-derived A plus rank-sliced broadcast and account for any full-rank residual, or label the metric “logical fp32 uplink only”; measure both directions' actual serialized bytes before claiming end-to-end communication savings.

12. **MAJOR — The pinned install cannot run the advertised full CPU test suite.** `requirements.txt:1-63`; `tests/test_flower_adapter.py:4`; `README.md:6-15`. `flwr` is imported by three Flower adapter tests but absent from `requirements.txt`, despite the Flower README specifying version 1.39. In the available Python 3.11 environment, `pytest -q tests` stops during collection with `ModuleNotFoundError: flwr`; the 14 non-Flower CPU contract tests pass. **Fix/experiment:** pin compatible `flwr` (and any required dependencies), then verify `uv venv --python 3.11`, install-from-requirements, and the full CPU suite from a fresh environment. No venv or dependency was created during this review.

13. **MAJOR — “No spike” does not resolve per-round dropout stability.** `components/orchestrator/simulate.py:35,101-105,126-127`; `eval/dropout_analysis.py:39-45`; `components/device_simulator/profiles.py:27,47-53`. Loss is evaluated only every third round, so `max_spike=0` cannot exclude a spike and recovery inside that window. The dropout analysis takes the maximum over *all* evaluated rounds, not specifically outage onset/rejoin; the forced c4 outage is five wholly offline rounds, whereas “partial” cut-offs are a step-count simulation rather than measured wall-clock deadlines or a killed node. **Fix/experiment:** score each round around cut-off, outage and rejoin; isolate the max after onset and after rejoin, include a c0 outage and a no-replay control, and use a measured deadline/Flower kill before implying physical mid-round stability.

14. **MINOR — The retrospective bounded-share column reports fabricated zeros.** `eval/summarize.py:101-106,119-122`; `eval/results/v1_summary.md:7-10,30-35`. `v1` rows predate `dominance_c0_norm`, but `r.get("dominance_c0_norm", 0.0)` renders their “c0 share (norm)” as **0.000** and commits zeroes to `v1_canonical.json`, rather than “not measured.” **Fix:** emit N/A/null for missing metrics and refuse to turn absent pilot measurements into numeric evidence. The summarizer docstring also references `scripts/check_numbers.py`, which is not present at this revision; add that check before claiming canonical-number enforcement.

## Things that are correct

- Anchor's default direction is sliced `ΔB_k / steps_done`, clipped in B space, then scaled by uniform weights and `tau_eff` from **planned** steps; that is the stated *FedNova-style heuristic*, not a proof of FedNova's guarantees with AdamW. Memory retains the last normalized/clipped direction through age 4; the optional per-column rule divides only among column owners. The shared frozen A makes the resulting product-space **delta** sum algebraically exact.
- FFA-LoRA's frozen A/B-only `n_k` average matches [§4, Eq. (4)](https://arxiv.org/html/2403.12313#S4.E4); FlexLoRA's `n_k` product average, SVD, and rank-specific factors match [§3.2](https://arxiv.org/html/2402.11505#S3.SS2). The paper-core issues above concern experimental controls and served-model reporting, not swapped equations.
- FedAvgAB does the claimed sample-weighted, factor-by-factor average with zero-padding for heterogeneous ranks; its product-space error is expected rather than an implementation of product averaging.
- CPU checks: 14 contract tests passed; FedAvgAB's sliced upload equals zero-padded full width bit-for-bit in the existing test, and an additional `anchor_full` CPU check did likewise with a nonzero high-rank global B. `4 * numel` is correct for fp32 logical payload bytes.
- The availability RNG is seeded independently of strategy and consumes the same default-device draws under exclusions; wiki train/test and distinct file paths are separated. Paired t intervals are computed with the correct standard-error and t critical value when the seed and provenance prerequisites hold.
