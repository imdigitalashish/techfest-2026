## 1. OneNet — Online Ensembling Network (NeurIPS 2023)
- **URL**: https://arxiv.org/abs/2309.12659 (accessed 2026-10-04)
- **Core idea**: Dynamically ensemble two online forecasters — one modeling temporal (within-variable) dependence, one modeling cross-variate dependence — with weights updated via an online-convex-programming / RL-based combiner so the mixture tracks whichever sub-model currently fits the regime.
- **Guarantee**: Framed as online convex programming (weight update has the flavor of online gradient/mirror descent over the simplex of two experts); no formal regret bound stated in the abstract — UNVERIFIED beyond that framing.
- **Per-update compute cost**: Two base forecasters' forward+backward pass plus a lightweight RL-style weight update per step — UNVERIFIED exact FLOPs/latency (not in abstract).
- **Reported result**: ">50% reduction in online forecasting error vs SOTA" per abstract (exact benchmark/metric not specified on this page) — quoted from abstract, mark as abstract-level claim not independently verified by us.
- **Code**: https://github.com/yfzhang114/OneNet (per abstract; not yet opened — UNVERIFIED stars/last commit).
- **Fit for sub-ms/ms budget**: Two-model ensemble roughly doubles inference cost vs single model; weight-combination step is O(1) (two scalars) so marginal overhead is tiny — the dominant cost is running 2 base nets, which must each already fit the latency budget.

## 2. DoubleAdapt (KDD 2023) — meta-learning incremental adaptation for stock trend forecasting
- **URL**: https://arxiv.org/abs/2306.09862 (accessed 2026-10-04). Authors: Zhao, Kong, Shen.
- **Core idea**: Two learned "adapters" — a *data adapter* that transforms incoming incremental data into a locally-stationary distribution, and a *model adapter* that gives a good parameter initialization — both optimized via meta-learning (MAML-style) so each new incremental update step is a fast, few-shot adaptation rather than full retraining.
- **Guarantee**: None stated (empirical meta-learning paper, no regret/PAC bound in abstract) — UNVERIFIED.
- **Per-update compute cost**: Abstract claims "considerable efficiency" vs. baselines but gives no FLOPs/latency numbers on this page — UNVERIFIED exact cost; architecturally it's a bi-level (meta-learned) fine-tune per incremental step, i.e., cheaper than full retrain but more than a single gradient step.
- **Code**: not given on abstract page — UNVERIFIED (known community repo exists; not opened in this pass).
- **Fit for sub-ms/ms budget**: Designed for daily-bar stock incremental updates (periodic retraining cadence), not per-tick inference — the adapters operate at the *update/training* cadence, not per-prediction, so added inference-time latency should be ~0, but update-time cost is non-trivial (meta-learned fine-tune) and likely too slow for intra-tick retraining; better suited to periodic (e.g., per-bar) regime recalibration than sub-ms per-event adaptation.

## 3. DDG-DA (AAAI 2022, Microsoft/Qlib) — Data Distribution Generation for predictable concept drift
- **URL**: https://arxiv.org/abs/2201.04038 (accessed 2026-10-04). Authors: Li, Yang, Liu, Xia, Bian.
- **Core idea**: Instead of reactive drift *detection*, train a predictor of how the data distribution itself will evolve, use it to generate synthetic/resampled future-like training data, then train the forecaster on that generated data — i.e., forecast the drift, not just the series.
- **Guarantee**: None (empirical); explicitly targets *predictable* concept drift (environments with exploitable structure in how drift evolves), not arbitrary/adversarial drift — UNVERIFIED formal bound.
- **Per-update compute cost**: Requires training a distribution-forecasting model in addition to the main forecaster, then periodically regenerating training data and retraining the main model — this is a periodic/batch retraining pipeline (Microsoft Qlib rolling-retrain style), not a per-tick update. UNVERIFIED exact wall-clock.
- **Results**: validated on stock price trend, electricity load, and solar irradiance forecasting, "significant improvement on multiple widely-used models" per abstract (no exact numbers on this page).
- **Code**: known to ship inside Microsoft/qlib (benchmarks/DDG-DA) — not opened in this pass, UNVERIFIED stars/last commit.
- **Fit for sub-ms/ms budget**: Not applicable at inference time (zero added inference cost once model is trained) but the *adaptation mechanism itself* operates on a slow (periodic retrain) cadence — unsuitable if regimes shift faster than the retrain period; a reasonable model for "slow regime" layer in a two-speed system, not for per-event adaptation.

## 4. FSNet — Learning Fast and Slow for Online Time Series Forecasting (ICLR 2023)
- **URL**: https://arxiv.org/abs/2202.11672 (accessed 2026-10-04). Authors: Pham, Liu, Sahoo, Hoi (Salesforce).
- **Core idea**: Complementary Learning Systems (CLS)-inspired online forecaster: a slowly-learned backbone is dynamically adjusted by (1) a per-layer **adapter** that monitors each layer's contribution to loss and does fast local adaptation, and (2) an **associative memory** that stores/retrieves representations of recurring past patterns — so abrupt *new* shifts get fast local adaptation while *recurring* regimes get recalled rather than relearned.
- **Guarantee**: None stated — empirical/architectural, no regret or convergence bound in abstract — UNVERIFIED.
- **Per-update compute cost**: Adds a per-layer adapter (monitors+gates each layer) and an associative memory read/write per step on top of the backbone forward/backward pass — strictly more than vanilla SGD fine-tuning but same order of magnitude (no FLOPs number given) — UNVERIFIED exact overhead.
- **Code**: https://github.com/salesforce/fsnet (per abstract; not opened — UNVERIFIED stars/last commit).
- **Fit for sub-ms/ms budget**: Per-step online update (not periodic batch retrain) so it's architecturally in the right latency class for streaming adaptation, but memory read/write + per-layer monitoring adds real overhead per step; needs profiling against a sub-ms budget — plausible for ms-scale, risky for sub-ms without a lightweight backbone.

## 5. DAIN — Deep Adaptive Input Normalization for Time Series Forecasting (2019; journal/IEEE TNNLS version)
- **URL**: https://arxiv.org/abs/1902.07892 (accessed 2026-10-04). Authors: Passalis, Tefas, Kanniainen, Gabbouj, Iosifidis.
- **Core idea**: A learned, end-to-end-trainable normalization *layer* (not a fixed z-score/min-max) that adaptively shifts/scales/gates the input distribution per-sample, conditioned on a summary of the current window, so the backbone always sees an approximately stationary input even as the raw series' distribution drifts — explicitly validated on a **large-scale limit order book dataset** plus load forecasting.
- **Guarantee**: None (empirical neural layer) — UNVERIFIED formal bound.
- **Per-update compute cost**: Adds one small extra sub-network (summary statistics → shift/scale/gate) evaluated once per input window at both train and inference time — low overhead, O(window-summary) not O(full backbone), likely cheap enough for ms-scale budgets. Key property: "can be directly applied to any new time series without requiring re-training" (quoted) — i.e., adaptation happens at inference time via the learned statistics function, not via online weight updates.
- **Code**: not given on abstract page — UNVERIFIED (community PyTorch ports exist; not opened in this pass).
- **Fit for sub-ms/ms budget**: Good candidate — it's a cheap normalization layer, not a retraining loop, so the adaptation cost is folded into one extra forward pass per inference, and it was *literally evaluated on LOB data* (directly on-topic for P04).

## 6. Adaptive Conformal Inference (ACI) Under Distribution Shift — Gibbs & Candès, 2021
- **URL**: https://arxiv.org/abs/2106.00170 (accessed 2026-10-04).
- **Core idea**: Wrap any black-box point/quantile predictor with an online update to the conformal miscoverage-target parameter α_t: after seeing each outcome, nudge α_t by a step proportional to (miscoverage indicator − target rate), so the prediction-interval width self-adjusts to track whatever the current error distribution is — explicitly drops the exchangeability assumption of classical conformal prediction.
- **Guarantee**: "Provably achieves the desired coverage frequency over long-time intervals irrespective of the true data generating process" (quoted) — i.e., a long-run empirical-coverage guarantee under arbitrary (even adversarial) distribution shift, not a per-step guarantee.
- **Per-update compute cost**: One scalar parameter (α_t) updated by one arithmetic step per observed outcome — O(1) per update, essentially free; cost is dominated by whatever black-box model produces the underlying point/quantile prediction.
- **Code**: not stated on this page — UNVERIFIED (known author repo ` isgibbs/AdaptiveConformal` exists per general knowledge; not opened in this pass).
- **Fit for sub-ms/ms budget**: Excellent fit — O(1) scalar update per tick makes this essentially free to bolt onto any LOB forecaster as a self-calibrating uncertainty band that widens automatically when the realized regime no longer matches training.

## 7. Conformal PID Control for Time Series Prediction — Angelopoulos, Candès, Tibshirani, 2023
- **URL**: https://arxiv.org/abs/2307.16895 (accessed 2026-10-04).
- **Core idea**: Reframes online conformal interval-width adaptation as a **control-theory problem**: treat the (target coverage − realized coverage) signal as an error to drive a PID (proportional-integral-derivative) controller that outputs the interval width/quantile adjustment, explicitly adding terms for scorecasting (anticipating systematic error from seasonality/trend) on top of plain integral (ACI-style) control — abstract states this "simplifies and strengthens existing analyses in online conformal prediction" (i.e. generalizes/unifies ACI).
- **Guarantee**: Formal online coverage guarantees (same family as ACI: long-run coverage irrespective of the data process) — exact theorem statement not reproduced here (not opened beyond abstract) — UNVERIFIED precise bound constants.
- **Per-update compute cost**: PID update is a handful of scalar operations (P + I + D terms) per tick, i.e., O(1), same cost class as ACI — cheap.
- **Validated on**: COVID-19 death forecasting (beat the CDC ensemble on coverage, per abstract), electricity demand, **market returns**, and temperature, using AR/Theta/Prophet/Transformer backbones. Authors note "an extendable codebase for testing" — implies public code (URL not shown on this page — UNVERIFIED exact repo link/stars).
- **Fit for sub-ms/ms budget**: Excellent — same O(1)-per-tick profile as ACI, with built-in handling of systematic/trend error, directly relevant for calibrated uncertainty bands around a LOB forecaster at tick-level cadence; "market returns" experiment makes it one of the more directly on-domain items in this scan.

## 9. Strongly Adaptive Online Learning — Daniely, Gonen, Shalev-Shwartz (ICML 2015)
- **URL**: https://arxiv.org/abs/1502.07073 (accessed 2026-10-04).
- **Core idea**: Defines "strongly adaptive" algorithms as ones whose regret is near-optimal on **every** contiguous sub-interval of time (not just over the whole horizon), and gives a generic black-box **reduction** that converts any standard low-regret ("weakly adaptive") online learner into a strongly adaptive one. This is the general theoretical ancestor of "adaptive regret" that motivates Fixed-Share-style and interval-ensemble approaches to tracking regime changes.
- **Guarantee**: Formal regret bound of the form: for any algorithm with static regret R(T), the reduction yields strongly-adaptive regret that is near-optimal simultaneously on every interval [r,s] ⊆ [1,T] — exact polynomial/log factors not reproduced here (would require reading body/theorems) — UNVERIFIED exact constants from this abstract-only pass.
- **Per-update compute cost**: The classic strongly-adaptive reduction (cf. "Follow the Leading History"/geometric covering intervals) runs O(log T) parallel instances of the base learner and combines them — i.e., per-step cost is O(log T) × (base learner's per-step cost), not O(1) — UNVERIFIED exact constant from abstract (this is general knowledge of the construction family, not from the fetched page).
- **Code**: none given (theory paper) — N/A.
- **Fit for sub-ms/ms budget**: The log T factor is a real concern for sub-ms budgets if T is large (long-running tick stream); still likely cheap in absolute terms (log T ~ 20-30 "expert" copies for T~10^9 ticks) if the base learner itself is trivial (e.g., a linear model), but stacks badly if the base learner is already a deep net — most useful as the theoretical justification for lighter practical schemes (Fixed-Share, windowed ensembles) rather than directly implemented at tick rate.

## 10. AdaHedge / FlipFlop — "Follow the Leader If You Can, Hedge If You Must" (JMLR; arXiv v2)
- **URL**: https://export.arxiv.org/abs/1301.0534 (accessed 2026-10-04) — note: direct arxiv.org mirror had a transient transport failure, export.arxiv.org mirror worked; author list was cut off in the fetched snippet (commonly attributed in the literature to de Rooij, van Erven, Grünwald & Koolen — **UNVERIFIED from this fetch**, names not actually visible in the retrieved text).
- **Core idea**: FTL (Follow-the-Leader) gets constant regret in stochastic/benign settings but can fail badly adversarially; Hedge-style methods are worst-case safe but overly conservative when the data isn't adversarial. **AdaHedge** is a parameter-free way to tune Hedge's learning rate on the fly (no "doubling trick", refines Cesa-Bianchi/Mansour/Stoltz 2007) and **FlipFlop** interleaves AdaHedge with FTL to get regret within a constant factor of FTL's (good) regret while *keeping* AdaHedge's worst-case guarantee — i.e., adaptively picks "trust the leader" vs. "hedge safely" depending on how adversarial the stream currently looks.
- **Guarantee**: Formal worst-case regret bounds for both AdaHedge and FlipFlop (exact bound expressions not reproduced here — body not opened, abstract only) — UNVERIFIED exact constants; qualitatively: invariant to rescaling/translation of losses, no need to know loss range in advance, losses may be negative (gains).
- **Per-update compute cost**: Hedge-family update — O(N) per round for N experts (one multiplicative-weight update + one learning-rate recompute), i.e., linear in number of experts/models being mixed, not in model size — cheap if N (number of regime-heads) is small.
- **Code**: none given on this page — UNVERIFIED (reference implementations exist in various online-learning repos, e.g. within research code for expert-tracking; not opened in this pass).
- **Fit for sub-ms/ms budget**: Very good — O(N) scalar weight update per tick across a small number N of regime-expert heads is cheap, and removes the need to hand-tune a mixing learning-rate, which is attractive for a regime-adaptive multi-head LOB forecaster (the "stretch" goal in P04).

## 0. Proceed — Proactive Model Adaptation Against Concept Drift for Online Time Series Forecasting (KDD 2025) [NEWEST]
- **URL**: https://arxiv.org/abs/2412.08435 (accessed 2026-10-04). Authors: Lifan Zhao, Yanyan Shen (SJTU).
- **Core idea**: Directly targets the **label-delay problem**: ground truth for a sample is only available after the forecast horizon, so by the time you can compute an online-learning gradient, there's already a gap between the training sample and the *current* test sample — and that gap is itself a source of concept drift ("adapting to outdated concepts"). Proceed (1) estimates the concept drift between the most-recently-available training samples and the current test input, (2) feeds that drift estimate through a learned **adaptation generator** that directly outputs parameter adjustments (not gradient steps) to proactively adapt the model to the current test sample *before* the true label ever arrives, and (3) is meta-trained on synthetic diverse concept drifts for generalization.
- **Guarantee**: None (empirical) — UNVERIFIED formal bound.
- **Per-update compute cost**: One drift-estimation step + one forward pass through an "adaptation generator" network per test sample (replaces a gradient-descent update with a learned direct mapping to parameter deltas) — architecturally this trades a backprop step for a (presumably smaller) generator forward pass, but exact FLOPs not given on this page — UNVERIFIED exact cost.
- **Results**: "brings more performance improvements than state-of-the-art online learning methods" on five real-world datasets across multiple backbone forecasters (per abstract; no exact numbers on this page).
- **Code**: https://github.com/SJTU-DMTai/OnlineTSF (stated in abstract; not opened — UNVERIFIED stars/last commit).
- **Fit for sub-ms/ms budget**: **Directly answers the thread's question "does label delay matter at short horizons?" — yes, explicitly, this is the paper's whole premise**: even without adversarial drift, the mere act of delaying labels by the horizon length manufactures a drift between train and test concepts. For P04 (short horizon k), this means the label-delay gap is small in wall-clock terms but may still be non-trivial in tick-count terms during fast regime changes. Cost-wise: proactive parameter adaptation per test sample is heavier than a pure-inference forward pass — likely too heavy for sub-ms unless the "adaptation generator" is tiny; more plausible at a coarser (e.g., per-N-ticks) adaptation cadence layered under a cheap per-tick predictor.

## TAFAS — Battling the Non-stationarity in Time Series Forecasting via Test-time Adaptation (AAAI 2025)
- **URL**: https://arxiv.org/abs/2501.04970 (accessed 2026-10-04). Authors: HyunGi Kim, Siwon Kim, Jisoo Mok, Sungroh Yoon.
- **Core idea**: A **test-time adaptation (TTA)** framework specifically for time-series forecasting (TSF-TTA): adapts a frozen pre-trained source forecaster to continuously shifting test distributions using **partially-observed ground truth** (i.e., whatever labels *have* become available by the current step, even if incomplete for the full horizon) plus a **gated calibration module**, while explicitly trying to preserve the pretrained semantic/backbone knowledge (avoid catastrophic forgetting) — model-agnostic wrapper, not a new backbone.
- **Guarantee**: None stated — empirical — UNVERIFIED.
- **Per-update compute cost**: Gated calibration module adds a small adapter network evaluated per test step, operating on top of a frozen backbone — cheaper than fine-tuning whole backbone, but exact overhead not given — UNVERIFIED.
- **Results**: "especially in long-term forecasting scenarios that suffer from significant distribution shifts" per abstract (no exact numbers captured on this page).
- **Code**: https://github.com/kimanki/TAFAS (per abstract; not opened — UNVERIFIED stars/last commit).
- **Fit for sub-ms/ms budget**: Relevant design pattern for P04 — "partially-observed ground truth" is directly analogous to using whatever same-timestamp signals (e.g., realized spread/trade prints before the full horizon label is known) are available before the full-horizon label arrives, letting the model calibrate on partial information rather than waiting the full label delay. A gated small-adapter-on-frozen-backbone pattern is latency-friendly if the adapter is tiny relative to the backbone.

## SAN — Adaptive Normalization for Non-stationary Time Series Forecasting: A Temporal Slice Perspective (NeurIPS 2023)
- **URL (search-verified, not yet opened as a primary page)**: https://proceedings.neurips.cc/paper_files/paper/2023/hash/2e19dab94882bc95ed094c4399cfda02-Abstract-Conference.html ; code https://github.com/ustc-time-series/SAN — found via web_search (AI-generated summary), **NOT independently opened via web_fetch in this pass — treat core-idea description below as UNVERIFIED-by-direct-read, sourced only from search summary**, accessed 2026-10-04. Authors (per search): Liu, Cheng, Li, Huang, Liu, Xie, Chen.
- **Core idea (per search summary only)**: Instead of normalizing a whole input window with one global mean/std (as RevIN does), split the window into smaller **temporal slices** and normalize each slice separately; a small **statistics-prediction module** forecasts the mean/variance of *future* slices so denormalization of the model's output can use predicted-future statistics rather than only past statistics — model-agnostic, pluggable into any backbone.
- **Guarantee**: None (empirical) — UNVERIFIED.
- **Per-update compute cost**: One small auxiliary statistics-prediction network evaluated per slice per window — UNVERIFIED exact overhead (not opened).
- **Fit for sub-ms/ms budget**: Same family as RevIN/DAIN (a normalization layer, not a retraining loop) so plausibly cheap, but slicing + a learned future-statistics predictor is strictly more machinery than RevIN's simple running mean/std — UNVERIFIED whether the overhead is negligible at tick rate; flagged for follow-up direct read.

## 8. RevIN — Reversible Instance Normalization for Accurate Time-Series Forecasting against Distribution Shift (ICLR 2022)
- **URL**: https://github.com/ts-kim/RevIN (official repo README, accessed 2026-10-04). Authors: Taesung Kim, Jinhee Kim, Yunwon Tae, Cheonbok Park, Jang-Ho Choi, Jaegul Choo. Note: the canonical paper page is OpenReview (https://openreview.net/forum?id=cGDAkQo1C0p) but that URL returned a bot-check wall ("Verifying your browser") when fetched directly on 2026-10-04 — used the official GitHub README instead, which quotes the abstract. A web-search-suggested arXiv ID (2105.07922) was checked and is **confirmed wrong** — that ID actually resolves to an unrelated eigenvalue-conditioning math paper; this illustrates why every claim here is fetch-verified rather than trusted from search summaries alone.
- **Core idea**: A simple, learnable, **symmetric normalize→denormalize** layer: compute per-instance mean/std, normalize the input with a learnable affine transform before the backbone, then apply the *inverse* transform to the backbone's output — removes distribution-shift-sensitive statistics going in and restores them going out, with the learnable affine giving the net some control over how much to trust the instance statistics.
- **Guarantee**: None (empirical) — UNVERIFIED formal bound.
- **Per-update compute cost**: O(window length × num features) to compute mean/std once per instance, plus one elementwise affine transform at input and one at output — very cheap, no extra network, just statistics + 2 elementwise ops.
- **Code**: https://github.com/ts-kim/RevIN — PyTorch, usage shown as a 3-line wrap (`revin_layer(x_in,'norm')` ... `revin_layer(x_out,'denorm')`); repo card shows "ICLR 2022" in title; exact star count/last-commit date not captured in the fetched README text — UNVERIFIED precise numbers.
- **Fit for sub-ms/ms budget**: Among the cheapest options in this scan — just running mean/std + affine, no extra forward network, trivially fits a sub-ms budget; the natural "default-on" baseline normalization for any LOB forecaster in P04.
