# SOTA for capture → 3D Gaussian-splat web twin (verified 2026-10-04)

> Every row below was opened at its primary source (arXiv abstract page, GitHub repo README/LICENSE/releases/source, or CVF/OpenReview) on **2026-10-04**. Anything not opened directly is explicitly marked **UNVERIFIED (lead only)**. Web-search prose is never cited as fact by itself — see per-claim citations.

## TL;DR — concrete recommendations for our pipeline

1. **Keep Brush, but build from `main`, not the v0.3.0 binary.** Only 3 git tags exist (`brush-0.0.1`, `0.2.0`, `v0.3.0`, 2025‑09‑14) — there is **no v0.4/v0.5 release**. Mip-Splatting anti-aliasing (PR #337), a fused SSIM+L1 kernel, 4× pixel-memory reduction, ~50% faster radix sort and +10‑15% render speed are all sitting **unreleased on `main`** today. `cargo build --release` from `main` is the single highest-value, lowest-risk speed-up available to us before 17 Nov. [github.com/ArthurBrussee/brush/blob/main/CHANGELOG.md, github.com/ArthurBrussee/brush/releases — 2026-10-04]
2. **Do not swap in VGGT/VGGT-Ω/MapAnything/DA3 as a hard dependency for the M5 path yet** — none of their READMEs mention MPS; all hardcode `cuda`/`cpu` device strings, and the heavier ones (VGGT-Ω 1B, DA3-Giant 1.15B) need 7–43 GB just for inference on an A100, which is risky on a 24 GB unified-memory M5 with no CUDA. Treat feed-forward posing as a **cloud-GPU (Azure) path**, not a Day-1 M5 path, until tested.
3. **On the Azure GPU path, the officially-documented, license-cleanest recipe is: MapAnything (Apache-2.0 code, true metric scale, up to ~2000 views) → COLMAP-format export → gsplat (Apache-2.0) short refine.** Meta's own VGGT README documents the identical pattern (`demo_colmap.py` → `gsplat/examples/simple_trainer.py`), so this is a vendor-blessed pipeline, not a guess. [github.com/facebookresearch/vggt README "Integration with Gaussian Splatting" — 2026-10-04]
4. **Watch the licenses carefully — they vary per checkpoint, not just per repo.** VGGT code is commercial-friendly since 2025-07-29 but only the gated `VGGT-1B-Commercial` checkpoint is; the default checkpoint stays non-commercial. VGGT-Ω is 100%-non-commercial (FAIR Noncommercial Research License, confirmed from the raw LICENSE file). Depth Anything 3 is Apache-2.0 for Base/Small/Metric/Mono but **CC BY-NC-4.0 for Giant/Nested — which are exactly the checkpoints with the 3D-Gaussian output head.** π³/Pi3X code is BSD-3 but weights are CC BY-NC-4.0. MASt3R/MASt3R-SfM is CC BY-NC-SA-4.0 end-to-end. Only **MapAnything (Apache-2.0)** and **AnySplat (MIT)** are clean for a shippable product.
5. **For true Apple-silicon-native GPU splat training, OpenSplat has real, primary-source-confirmed Metal/MPS support** (`GPU_RUNTIME` defaults to `MPS` on macOS; falls back to CPU only if the Metal toolchain is missing) — but it is AGPLv3 and, per a third-party M-series benchmark we could not independently verify, trains slower (~42 min/15k iters on a "garden"-class scene) than our current Brush run. Keep Brush as primary; keep OpenSplat only as a fallback/cross-check, not for speed.
6. **A brand-new pure-PyTorch Metal trainer (`tchauffi/metalsplat`, MIT) appeared ~5 weeks ago (first push 2026-09-07)** and claims full 3DGS/2DGS training on MPS with no Xcode dependency. It is unproven (10 ★) — worth a 15-minute sandboxed trial, but too risky to depend on for Round 1/Round 2 deadlines without a tested fallback.
7. **AnySplat is the only feed-forward-Gaussian model that is MIT-licensed end-to-end and documents its own "feed-forward init + short post-opt" recipe** (`src/post_opt/simple_trainer.py`) — exactly our target recipe — but it is CUDA-only (torch 2.2.0+cu121) with no MPS mention, so it is cloud-GPU-only for us, and we could not verify a concrete frame-count ceiling or fps figure from its README.
8. **Indoor appearance/exposure fixes are shipping in Apache-2.0 `gsplat` today, confirmed by reading its source directly**: `simple_trainer.py` has `load_exposure: bool = True # Load EXIF exposure metadata from images`, plus `AppearanceOptModule`/`CameraOptModule` (`app_opt`, `pose_opt` flags) and a built-in `MCMCStrategy` (the 3DGS-MCMC densifier). If we ever move training off Brush onto a CUDA box, gsplat already has the indoor-robustness knobs we'd otherwise have to hand-roll.

## Recommended recipe for <20 min

### On the M5 Mac (today, no CUDA)
1. **Capture discipline, not new models, is the biggest lever right now**: fewer, better-spaced frames (150–200 instead of 263) with sequential-matching COLMAP still converges; cutting frame count is the only *already-verified-safe* way to cut both the SfM and splat-training stages simultaneously.
2. **Rebuild Brush from `main`** (not the v0.3.0 binary) to pick up the fused SSIM+L1 kernel, 4× pixel-memory cut, ~50%-faster radix sort and +10–15% render speed that are currently unreleased — this directly attacks our 37-minute, 15k-step number with no pipeline redesign and no licence change (still Apache-2.0).
3. **Enable the Mip-Splatting 2D filter** (now on `main`) for indoor anti-aliasing quality at no extra cost once built from source.
4. Keep **pycolmap 4.2.1 SIFT + sequential matching + global mapping** as-is for now — none of the feed-forward posing models have confirmed MPS support, and the heavyweight ones (VGGT-Ω, DA3-Giant, MapAnything) risk OOM/slowness on 24 GB unified memory with CPU fallback. If time allows, **sandbox-test** `tchauffi/metalsplat` (MIT, native MPS, ~4 weeks old) on a small scene as a possible future Brush alternative — but keep Brush as the committed path.
5. Keep **OpenSplat** installed as a documented, Metal-confirmed fallback only (AGPLv3; reportedly slower than Brush per an unverified third-party benchmark) in case Brush's `main` branch misbehaves on event day.

### On a cloud GPU (once Azure quota lands)
1. **Pose/geometry**: run **MapAnything** (Apache-2.0 code, explicit metric scale, up to ~2000 views in one pass) on all captured frames — this replaces SIFT+matching+BA entirely with a single feed-forward pass. Cross-check the exact weight licence for the default `facebook/map-anything` checkpoint vs. the explicitly-named `facebook/map-anything-apache` variant before shipping (flagged gap above).
   - If MapAnything underperforms indoors, fall back to VGGT's **gated commercial checkpoint** (`VGGT-1B-Commercial`) — same `demo_colmap.py` export path, Meta-documented.
2. **Export to COLMAP format** (both MapAnything and VGGT support this pattern; VGGT ships `demo_colmap.py` directly).
3. **Short gsplat refine** (Apache-2.0): enable `--pose_opt`, `--app_opt` (appearance/exposure embedding) and `load_exposure=True` for indoor photometric robustness, and the built-in `MCMCStrategy` for deterministic, high-quality densification in a capped iteration budget (literally the same algorithm as 3DGS-MCMC/Brush's "MCMC-like" growth, now Apache-licensed). A few thousand iterations instead of 15k should suffice once Gaussians start from a correct, metric-scale, feed-forward init rather than from sparse COLMAP points.
4. **Total budget estimate**: feed-forward pose/points in seconds-to-low-minutes (per VGGT's own "<1 second" reconstruction claim, scaled to 263 frames) + a short (2–5 min on a modern NVIDIA GPU, unverified by us for our exact scene) gsplat refine ≈ plausibly **under 10–15 minutes**, leaving headroom under the <20 min target for export/packaging into the web viewer. **We did not benchmark this ourselves — treat the time estimate as a hypothesis to validate on the first Azure GPU session, not a verified number.**
