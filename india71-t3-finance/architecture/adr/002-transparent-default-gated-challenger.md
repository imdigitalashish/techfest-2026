# ADR 002 — C6 ships a transparent default rule; the learned model is a gated challenger

- **Status:** accepted, 2026-10-04 14:12 IST. Supersedes the allocation part of ADR 001's spike A (the spike itself stands).
- **Context.** v0.1 (uplift model + budgeted allocation) captured 0.33 of the achievable gain against 0.37 for "best average arm to everyone" (SYNTHETIC; `eval/results/c6_exp1.json`). The Supervisor's evidence-honesty rule: either beat the rule in a pre-registered test or ship the rule and keep the model as a gated challenger. Dev diagnosis (seeds 0–2): the losses came from (a) not spending the leftover budget and (b) noisy per-person *arm choice* from a small pilot (~810 persons per arm); a real randomised e-mail experiment (Hillstrom) showed the same pattern — targeting *whom* helps when contacts are scarce, personalising *which* does not reliably help.
- **Decision.**
  1. **Default (deployed):** a transparent rule recomputable from the pilot table — stage 1, the arm with the highest pilot effect per rupee to every eligible person; stage 2, the leftover budget upgrades lottery-drawn persons to the arm with the best extra effect per extra rupee.
  2. **Challenger:** same arms; an uplift model chooses *whom* to upgrade (women ≥ their eligible share).
  3. **Gate:** the challenger replaces the lottery only where it beats the rule on held-out pilot data (IPW, one-sided 90% bootstrap bound > 0). Every plan keeps a 10% randomised holdout.
- **Evidence (pre-registered 14:00 IST, `eval/preregistration/c6_v02.md`; results `c6_v02_results.md`; SYNTHETIC seeds 10–19).** Challenger − rule = +0.079 (95% CI +0.058 to +0.100), positive in 10/10 worlds (H1 pass); rule − best-arm-only = +0.092 (H2 pass). The gate deployed the challenger in 0/10 worlds (~840 validation persons): too conservative at this pilot size. In 2/10 worlds the pilot ranked the arms wrongly (rule ≤ 0.08).
- **Consequences.** The proposal presents the rule as what runs, the model as a challenger with a stated entry test, and pilot size per arm as a design input. Future work: power the gate (larger or accumulating holdout; sequential testing), and an arm-ranking safeguard (e.g. never let stage 1 pick an arm whose pilot effect is not distinguishable from zero).
