# Pre-registration — C6 v0.2: does the learned "who-only" challenger beat the transparent rule?

- **Registered:** 2026-10-04 14:00 IST (clock time, `TZ=Asia/Kolkata`); the git commit that adds this file is the evidence of the time.
- **Registrant:** india71-t3-finance project lead.
- **Status:** registered before any run on the test seeds. Seeds 10–19 have never been simulated in this project.

## Code under test (frozen at the registering commit)
`components/targeting/policy_v02.py` (default rule, challengers, gate), `components/targeting/engine.py` (shrunk T-learner, `shrink = 0.5`), `components/simulator/` (SYNTHETIC worlds; `calibration.json`), `eval/pipeline.py`, `eval/targeting_v02_eval.py`, `eval/prereg_c6_v02_analysis.py`, `eval/frozen_allocate.py` (oracle).

## Design
- **Data:** SYNTHETIC simulator worlds, seeds **10–19** (10 worlds), 20,000 persons each, 20% randomised pilot (5 arms incl. no contact), budget ₹10 per eligible person (eligible = not in pilot and not already in meaningful use).
- **Outcome per policy:** normalised policy value = (V − V_random) / (V_oracle − V_random), V = expected incremental persons in meaningful use over six months from the simulator's true potential outcomes, each person counted once.
- **Policies:** `rule` = transparent default (stage 1: arm with the highest pilot effect per rupee to everyone; stage 2: leftover budget upgrades lottery-drawn persons to the arm with the highest extra pilot effect per extra rupee). `challenger_who` = same stage 1 and same upgrade arm; the model chooses *whom* to upgrade (women's share ≥ eligible share). Also reported: `random`, `status_quo`, `risk_bc`, `best_arm_only`, `uplift_v01`, `challenger` (model also picks the arm), `gated` (`challenger_who` only if the pilot gate passes, else `rule`), `oracle`.

## Hypotheses and tests (one-sided paired t-test across the 10 seeds, α = 0.05)
- **H1 (primary):** mean(`challenger_who` − `rule`) > 0. Pass iff the mean difference > 0 and p < 0.05.
- **H2 (secondary):** mean(`rule` − `best_arm_only`) > 0, same test.
- **Descriptive (no pass/fail):** `rule` − `status_quo`; `challenger` − `rule`; `gated` − `rule`; number of seeds where the gate passes; all policy means and standard deviations.

## Decision rule
- Whatever the outcome, the deployable default stays the **transparent rule**; the learned model runs only as a **gated challenger** (deployed only where it beats the rule on held-out pilot data).
- If H1 passes, documents may say: "in a pre-registered SYNTHETIC test (seeds 10–19), the learned who-only challenger beat the transparent rule by X (95% CI …)". If H1 fails, documents report the failure and make no claim that the model beats the rule.
- No re-runs with other seeds, no code changes before the run. Any deviation is appended below as a dated correction; registered text is never edited.
