- **Registered:** 2026-10-04 14:57 IST (clock time, `TZ=Asia/Kolkata`); the git commit that adds this file is the evidence of the time.
- **Why a new test:** the v0.2 registered test (`c6_v02.md`, results `c6_v02_results.md`) stands as reported, but the code review (`reviews/2026-10-04-code-gpt-6-sol.md`) showed that its "who-only" challenger did not match its registered description in seeds 12 and 15 (issue 1), the women's floor was not enforced on the deployable rule (issue 3), the gate validated a different model from the one deployed (issue 4), the holdout existed only as a contract field (issue 5), the model saw true covariates (issue 6), and the cohort was not PMJDY-specific (issue 7). v0.3 fixes these; this registration tests the fixed system on fresh seeds.
- **Seeds 20–29 have never been simulated in this project.**

`components/targeting/policy_v03.py`, `components/targeting/engine.py` (shrunk T-learner, `shrink = 0.5`), `components/simulator/` (PMJDY-calibrated; DBT-purpose accounts exempt from the official flag), `components/usage_state/classify.py`, `components/linker/link.py`, `eval/pipeline.py` (bank-observable proxies with stated error rates), `eval/targeting_v03_eval.py`, `eval/reference_allocate.py`, `eval/frozen_allocate.py`, `eval/prereg_c6_v03_analysis.py`.

## Design
- **Data:** SYNTHETIC simulator worlds, seeds **20–29**, 50,000 persons each, 30% randomised pilot (5 arms incl. no contact). Cohort: Jan Dhan holders (≥ 1 PMJDY account) not already in meaningful use. Budget Rs 10 per eligible person.
- **Pilot use:** split once 70/30; effects and model fitted on 70%; gate on 30%; deployment uses the same fitted objects.
- **Policies:** `rule` (transparent default: 10% gender-stratified holdout; stage 1 = cheapest arm not shown harmful, to every non-holdout eligible person or a women-floor-stratified lottery; stage 2 = leftover budget upgrades a women-floor-stratified lottery to the arm with the best extra effect per extra rupee); `challenger` (exact copy of the rule's plan except that the model chooses whom to upgrade); `gated` (challenger only if the gate passes, else rule). Also reported: `random`, `status_quo`, `risk_bc`, `best_arm_only`, `reference` (true effects; heuristic, not a certified optimum).
- **Outcome:** normalised value = (V − V_random) / (V_reference − V_random); V = expected incremental persons in meaningful use over six months (true potential outcomes, each person once).

## Hypotheses (one-sided paired t-test across the 10 seeds, α = 0.05)
- **H1 (primary):** mean(`challenger` − `rule`) > 0. Pass iff mean > 0 and p < 0.05.
- **H2:** mean(`rule` − `best_arm_only`) > 0, same test.
- **H3 (safety, pass/fail):** in all 10 seeds, `rule`, `challenger` and `gated` meet the women's floor (`floor_ok`), every policy stays within budget, and no holdout person receives outreach.
- **Descriptive:** `rule` − `status_quo`; `gated` − `rule`; gate passes; perfect-linkage sensitivity of `challenger` − `rule`; all means and SDs.

## Decision rule
The deployable default stays the transparent rule; the model runs only behind the gate. If H1 passes, documents may state its mean and 95% CI, labelled SYNTHETIC; if it fails, they report the failure. If H3 fails, no safeguard may be described as implemented until fixed and re-tested. No re-runs, no other seeds, no code changes before the run; deviations are appended as dated corrections.

## Disclosed development (seeds 0–2; `eval/results/c6_v03_dev.json`)
During development the stage-1 rule was changed from "best positive pilot effect per rupee" to "cheapest arm not shown harmful", after dev runs showed that a small pilot often mis-estimated the cheap arm's tiny effect as negative and the rule collapsed; the world size was raised to 50,000 persons with a 30% pilot so that about 900 persons per arm remain for fitting. Dev results at that setting: rule 0.470 ± 0.004, challenger 0.562 ± 0.015 (per-seed differences +0.097, +0.104, +0.076), best_arm_only 0.246, status_quo 0.033, risk_bc −0.092; floors met in all; gate passed 0/3; perfect-linkage challenger − rule +0.157, +0.121, +0.122.
