## (b) Per-source notes with evidence

**1. NASA T2 Portal — negative, well-verified.** Homepage (`technology.nasa.gov/api/`) documents the endpoint pattern `.../api/api/[patent|software|spinoff]/{keywords}` and gives a sample record as an **unnamed JSON array**: `["53f657...","ARC-14653-2","Air traffic management evaluation tool","Methods for...","patent_ARC-14653-2","aeronautics","","","","ARC"]`. I ran a live query (`.../api/patent/propulsion`) and got the same positional shape (title/description/case-id/category/3×blank/center/image/blank/score) for 3 real patents (`MFS-TOPS-120`, `LEW-TOPS-180`, `LAR-TOPS-352`); the 3 blank slots were blank in all 4 records I inspected (1 doc example + 3 live). I also opened the patent **detail HTML page** (`technology.nasa.gov/patent/MFS-TOPS-120`) and grepped it for `TRL|technology readiness|readiness level` — **zero matches**. Caveat: only 4 of ~1,400 patents sampled; not exhaustive.

**2. NASA NTRS — verified, usable as a proxy source.** `GET /api/citations/search?q="technology readiness level"&engine=version=3` → `"stats":{"total":530}`. Opened a full citation record (`/api/citations/20040161451`): fields are `copyright`, `subjectCategories`, `stiType`, `title`, `abstract`, `authorAffiliations`, `center`, `downloads[]` — **no structured TRL field**, but the abstract states in prose: *"the goal of these activities is to advance the **technology readiness level (TRL) of solar sail propulsion from 3 towards 6** by 2006"* — an explicit, regex-extractable number. The record's `copyright` object itself carries a machine-readable usage flag, e.g. `"determinationType":"GOV_PUBLIC_USE_PERMITTED"` — licence varies per record and is worth propagating into any derived dataset. The **plain-text full text download** works: `/api/citations/20040161451/downloads/20040161451.txt` → 18,317 bytes of OCR'd report text, directly usable (no PDF parsing needed), opening with the same TRL sentence verbatim. A separate query `q="techport"` returns 123 hits, including a record literally titled **"TechPort Abstracts"** (id `20205005780`, STI type `OTHER`, "Other - Technology development project abstracts") — this is TechPort content re-hosted inside NTRS, not an independent cross-link; it does not add new genre diversity.

**3. NASA TechPort "Document" library items — the strongest, most concrete finding.** Per the task's lead, TechPort projects carry `libraryItems[]`; items with `libraryItemType=="Document"` (title usually "Briefing Chart") have a `files[]` array with a `fileId`, e.g. project `93794` → item `367216` → `{"fileId":367952,"fileExtension":"pdf","fileName":"SBIR_2016_2_BC_S3_01-7259","fileSize":134826}`. I tested candidate download URLs with `curl`:
- `GET https://techport.nasa.gov/api/file/367952` → **HTTP 200**, `Content-Type: application/pdf`, **body is byte-identical in size to the declared `fileSize`** (134,826 bytes), and starts with the PDF magic bytes `%PDF-1.4` (`xxd` confirmed: `2550 4446 2d31 2e34`).
- `GET https://techport.nasa.gov/file/367952` (no `/api/`) → HTTP 200 but returns the TechPort Angular **app shell HTML**, not the file — a dead end if tried without `/api/`.
- `GET https://techport.nasa.gov/api/projects/93794/file/367952` → HTTP 404 (`{"...}`, 88 bytes) — wrong shape.

**Confirmed URL pattern: `https://techport.nasa.gov/api/file/{fileId}`.** Scanning our existing local cache (`.data/techport/raw/*.json.gz`, 11,427 projects, independent of network) for `libraryItemType=="Document"` with a `.pdf` file: **3,102 projects (27.1%) have ≥1 such PDF; 3,218 PDF items total; 3,066 of those projects also have a non-null `trlCurrent`.** TRL distribution among them is mid-skewed: `{0:5, 1:11, 2:100, 3:653, 4:1101, 5:524, 6:444, 7:156, 8:56, 9:16}` — TRL 3–6 dominate (SBIR Phase I/II norm), TRL 1/8/9 are rare (label-imbalance caveat for recipe below). These PDFs are short (the sampled one was 131 KB) slide-style "briefing chart" reports — a genuinely different surface form from the plain-prose `description` field already used for the primary TechPort training set, which is the genre-shift value here.

**4. EU CORDIS — mostly negative, with an important scope caveat.** The public OpenAPI spec for CORDIS's **"Data Extraction Tool"** (`cordis.europa.eu/dataextractions/api-docs`) is openly viewable without a key, but every operation (`getExtraction`, `cancelExtraction`, `deleteExtraction`) **requires a `key` query parameter** ("Users api key") — i.e. actually pulling bulk data needs registration. Grepping this entire spec for `readiness`/`"trl"` → **zero matches**, but this spec only documents the task-submission control layer, not a live per-project field list, so this is weak (not strong) negative evidence. Stronger evidence: I opened a live Horizon Europe project page directly, `cordis.europa.eu/project/id/101057733` ("REEPRODUCE"), and read its full `Objective` text — it discusses "pilots", "technologies successfully proven in previous projects" etc. but **contains no literal "TRL N" number** for this project. (Web search, **not independently verified**, claims some *call* texts state an expected TRL range, e.g. "TRL 7"; I did not open such a call page myself this session.)

## (c) Recommended genre-shift test-set recipe

**Pick 3 sources, ~300–500 documents total, held out and frozen, scored exactly like the hidden set (ordinal accuracy):**

1. **NASA TechPort "Document" Briefing-Chart PDFs** (verified, §3) — ~200 docs, **stratified-sampled across TRL 1–9** from the 3,066 locally-available labelled PDFs (oversample TRL 1/2/8/9, which have only 11–100/56/16 examples respectively, vs. hundreds at TRL 3–6) using the already-confirmed `GET /api/file/{fileId}` pattern. **Label = explicit**, same `trlCurrent` already used for the primary TechPort set. This is the lowest-risk, same-licence, zero-new-infrastructure addition — but it is a *compressed slide-deck* report sub-genre, so it alone does not cover the "patent" or "full-length paper" genres.
2. **NASA NTRS reports/conference papers** with an explicit `"TRL N"` (or `"TRL N to M"`) phrase extracted by regex from `abstract` or the downloaded `.txt` fulltext (query `q="technology readiness level"`, 530 candidates) — ~150 docs. **Label = proxy** (the clearly-asserted *current/achieved* TRL number, not a start/target figure); requires a human or LLM-judge spot-check on a ~30-doc sample because a document can mention multiple TRL numbers (own subsystem vs. a cited one, start vs. target). This is genuine full-length report/paper prose — the best full-text-genre complement to (1).
3. **DOE OSTI.gov reports** with the same regex-proxy technique (query `q="technology readiness level"`, 3,516 candidates) — ~100 docs. Same label-noise caveat as (2); adds a **non-NASA** institutional writing style, which matters because the hidden set is explicitly cross-domain (not space-specific).

**Known label noise to document in the eval card:**
- TechPort PDF labels are the *parent project's* TRL at crawl time; a Briefing Chart is often a mid-project status snapshot, so the true TRL-at-authorship may differ slightly (temporal lag).
- NTRS/OSTI proxy labels are self-reported by authors in free text, not independently audited; "TRL 3 towards 6" style ranges require a rule for which number is the document's "current" TRL (we recommend: the lower/starting number if explicitly called "current", else flag as ambiguous and exclude).
- Natural class imbalance (TRL 3–6 heavy, TRL 1/8/9 rare) persists across **all** sources checked — this mirrors the primary TechPort training set's imbalance, so stratified sampling (not random sampling) is required to get any signal at the extremes.
- **Do not include** the `vascoslopes272/eVTOL-Visual-Evaluation` patent↔TRL crosswalk in the frozen metric unless the author grants reuse permission (no LICENSE file); if used at all, treat it as a small (~20–50 doc) exploratory/patent-genre add-on clearly segregated from the scored set, since its labels are a single hobbyist's unaudited assessment.

## (d) Document-level TRL-prediction papers (text of a single document → TRL)

**None found and opened in this session.** Queries tried:
- arXiv API: `abs:"technology readiness level" AND abs:"classif"` → 4 total results (`export.arxiv.org/api/query?search_query=abs:%22technology+readiness+level%22+AND+abs:%22classif%22`); all reviewed — none predicts TRL from a single document's text (hits: an astronomical-transient-classification survey that only *mentions* TRL; a Mars-rover AI paper stating an *achieved* TRL 4 for its own system; a quadruped-robot security survey mentioning TRL in passing).
- Semantic Scholar Graph API: `"technology readiness level classification patent"` → 898 total hits; top 10 reviewed are all **domain-specific TRL assessment studies** using structured/expert inputs (self-healing concrete, fungal enzymes, bicycle safety, hydropower fuzzy-logic/ANN classifiers) — not general single-document NLP/LLM classifiers.
- Follow-up Semantic Scholar queries — `"large language model technology readiness level document classification"` and `"predicting technology readiness level from text"` — both **failed with HTTP 429** (rate-limited, no API key available) and could not be completed; marked **UNVERIFIED/incomplete**, follow-up needed with a key or paced requests.
- Web search (secondary, not independently opened) surfaced two **patent-NLP surveys** — arXiv:2403.04105 ("Natural Language Processing in the Patent Domain: A Survey") and arXiv:2404.08668 ("A Survey on Patent Analysis: From NLP to Multimodal AI", ACL 2025) — reported by the search engine to catalogue patent-NLP tasks broadly without spotlighting TRL prediction; I did not open these PDFs myself, so this absence claim is **UNVERIFIED** and flagged for a follow-up direct read.

**Conclusion:** consistent with `../landscape.md` §2's prior finding (bibliometric-aggregate or framework/checklist prior art only) — no public, document-level, NLP/LLM-based TRL 1–9 classifier was located. This supports treating a reproducible genre-shift benchmark as itself a contribution, not a replication of existing work.
