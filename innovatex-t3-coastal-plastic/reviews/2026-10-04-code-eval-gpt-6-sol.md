## Numbered issues

1. **BLOCKER — The stated <=5% MRV false-flag operating point is not used by the shipped reconciler.** `components/mrv_ledger/evaluate.py:70-75` calibrates `z_review=2.1419` on separate honest records, but `components/mrv_ledger/reconcile.py:30,81` defaults to `1.645`; `components/dashboard/build_bundle.py:114,134` passes a density-adjusted copy of that default. **Reproduce:** run `evaluate_reconciliation()` and, on its *same* 10,000 held-out honest / 5,000 fraudulent trips, compare `reconcile(record, capacity)` with `reconcile(record, capacity, replace(DEFAULT, z_review=z_thr))`. The default flags **902/10,000 = 9.02%** honest trips, with 78.24% fraud recall and **31.34%** precision at 5% prevalence; the calibrated path flags **470/10,000 = 4.70%**, with 71.64% recall and **44.51%** precision. The quoted 71.6% at <=5% false flags describes an offline rule, not the rule used for signed records. **Fix:** persist the calibrated threshold as a versioned parameter, use it in both evaluation and every reconciliation call (including the dashboard), and test the actual default path against the same holdout.

2. **MAJOR — Future sea-level data enters the "held-out" tide forecast.** `components/twin_sim/fetch_forcing.py:25-27,56-67,83-87` fits UTide once to *all* available marine sea levels and reconstructs the entire 2019-2025 forcing. `components/twin_sim/data/tide_fit.json:3-6` records the fit window as **2022-11-23 through 2025-09-30**, while `components/twin_sim/sim.py:18` declares 2024-2025 held out; `components/twin_sim/risk_forecaster.py:29` uses this same fitted tide to choose shifts. **Reproduce:** compare `tide_fit.json`'s `fit_period` with the `years` in committed `analysis.json` ([2024, 2025]). The forecast could not have been fitted that way when a 2024 or early-2025 shift was issued; the 0.079 m fit RMSE is expressly *in-sample* against model data, not held-out skill. **Fix:** freeze a tide fit at the training cutoff (at most 2023 for this comparison), generate 2024-2025 predictions from it, compare against held-out marine/gauge data separately, then rerun the paired policy analysis. Label any remaining tide oracle explicitly if retaining the existing sensitivity run.

3. **MAJOR — SYNTHETIC flux prediction and truth count different directions.** `components/detection/t3det/synth.py:99-106` labels only left-to-right line crossings as ground truth; `components/detection/t3det/run_flux.py:37-49` sets `direction=0` and counts *either* direction. **Reproduce:** `LineCrossingCounter(CountingLine((100,0),(100,200)), direction=0)` counts a track at x=110 then x=90 as one; the same track with `direction=-1` counts zero. The published 16-versus-12 (33.33%) figure can include reverse-direction false tracks. Absolute total-count error also permits misses and spurious crossings to cancel. **Fix:** derive the counter direction from `gt["direction"]` (left-to-right is `-1` for this line), rerun the synthetic sequence and report matched crossings plus false/missed counts alongside net count error.

4. **MAJOR — A trusted crew key can sign a record attributed to a different crew.** `components/mrv_ledger/chain.py:92-113` verifies a signature against `trusted_keys[signature.signer_id]` but never compares that ID with `entry.record.crew_id` (nor the signature's recorded `hash` with `entry.hash`). **Reproduce:** append a record whose `crew_id` is `SYN-crew-1`, sign its hash as `SYN-crew-2` using crew 2's registered key, and call `verify_signatures([entry], [signature], {"SYN-crew-2": public_hex(key2)})`: it returns `ok=True`. Without an anchor, a registered device could re-sign a consistent rewrite attributed to another crew; the campaign's 100% signature result tests rewrites with *old* signatures, not this case. **Fix:** bind signer identity (or a documented delegation) and signed hash to each entry, and test cross-crew re-signing as a negative case.

5. **MAJOR — `check_docs: 0` cannot establish that all numbers are bound or cited correctly.** `eval/check_docs.py:26-28,76-93` scans only >=4-digit integers, decimals, comma groups and percentages, waives *entire* `ASSUMPTION`/`UNVERIFIED` or self-cited lines, and checks fact numbers using substring inclusion in the whole fact row. **Reproduce without editing a template:** `nums("40 draws") == []`; `render_text("{{r:unknown")` leaves an unresolved tag and `nums` still finds nothing; `norm(nums("1,000 kg")[0]) in norm("11,000 kg")` is `True` even though the cited quantity differs by 10x. Those would evade the corresponding checks. **Fix:** reject unmatched placeholder syntax, tokenize and bind *all* claim numbers (with narrowly enumerated slide/date exceptions), and compare whole normalized number tokens to the fact's actual claim, not substrings anywhere in its row. Add adversarial checker tests.

6. **MINOR — The detector "trained vs off-the-shelf" sentence mixes AP evaluators.** `eval/doc_numbers.py:177-190` renders `0.857` from Ultralytics' trained `metrics.json.mAP50` beside `0.394` from the frozen matcher in `metrics_zeroshot.json`; `components/detection/results/metrics.json` already stores the apples-to-apples frozen trained result **0.8559** (versus frozen zero-shot **0.3935**). **Reproduce:** evaluate `doc_numbers.value("det_line")` and compare its 0.857/0.394 pair with `metrics.json["frozen_matcher_test"]["trained"]["mAP50"]` and `metrics_zeroshot.json["mAP50"]`. The difference is only 0.0015, but the comparison should use one scorer. **Fix:** say **0.856 vs 0.394 with the frozen matcher**, and quote 0.857 separately as the Ultralytics test result if desired.
