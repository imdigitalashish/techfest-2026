## 2. Issues

1. **critical - Confirmatory probability diagnosis reads the generating code instead of inferring it.** `eval/run_prob_pack.py:134-148`, `components/bugs/probability.py:49-99`. The evaluator gives its "engine" `x["code"]` and the targeted `x["bug"]`; it returns the code when the supplied answer equals that bug and abstains otherwise. A slip is deliberately chosen not to equal that bug. Thus 60/60 bug answers, 60/60 abstentions, 50% coverage, and both parts of H8 are guaranteed by construction, not independently confirmed diagnoses. The LLM prompt does **not** receive the target code, so the compared methods also have unequal information. The protocol does disclose that the synthetic result is by construction; the result should not be called empirical confirmation of a deployable general cascade. **Fix:** execute every applicable probability rule against the displayed problem, claim only a unique matching code, test slips against *all* rules, and evaluate separately labelled, non-generator-native items without giving the inference code its gold target.

2. **critical - Reported cascade cost/latency savings use the wrong population.** `eval/run_prob_pack.py:174-191`, `eval/run_cascade.py:97-107`. Both multiply the *all-item average* LLM cost and *all-item median* latency by the fraction routed to the LLM, although abstained-on items are more expensive and slower. Summing the committed per-item token usage only for the 60 routed slips gives GPT-5.5 **$5.0832/1,000**, not the reported **$3.6583**; GPT-5.4-mini gives **$2.1252**, not **$1.2275**. The routed GPT-5.5 latencies imply **2.6775 s per diagnosis before engine overhead**, not the reported **1.7623 s**. On real items, GPT-5.5 routed-token cost is **$6.1015**, not **$5.9462**. Calls halve by design on synthetic items; dollars do not. **Fix:** sum actual tokens and measured times for precisely the items the cascade routes, divide by the full item count, measure engine work, and distinguish mean per-diagnosis time from median call latency.

3. **major - Displayed fractions do not preserve executable bug semantics.** `eval/run_llm_gaps.py:101-108`, `components/bugs/school_math.py:149-156,171-175`. `show_llm` brackets each fraction literal, but parsing `(1/2) + (1/3)` discards its literal marker inside the parentheses, disabling `FRAC_ADD`: the original tokens produce `2/5`, whereas the same displayed expression reparsed by the engine produces the correct `5/6`. All 180 inversion keys survive this round trip, but **25/180 assigned misconception answers do not** (all involve `FRAC_ADD`). The engine therefore evaluates hidden token provenance that the LLM prompt does not encode in the same way. **Fix:** preserve simple fraction-literal provenance through grouping, assert displayed-expression/bug-answer round trips for every generated item, and append a protocol deviation before rescoring if prompts or items change.

4. **major - Percentile bootstrap CIs imply certainty after all-zero/all-one samples.** `eval/run_llm_gaps.py:132-138,251-260`; the same helper is used in `eval/run_prob_pack.py:112-125`. With zero false claims in 152 negatives it reports `[0, 0]`, while a two-sided exact 95% interval still permits an approximately **2.4%** false-claim rate; for 60/60 both-correct answers it reports `[1, 1]`, while the exact lower bound is about **94.0%**. The paired and P/N-stratified *resampling indices* for H1/H2 are appropriate, but a degenerate empirical distribution cannot measure unseen-error uncertainty or justify a "safe" stage. **Fix:** use binomial exact/Wilson intervals for standalone proportions and suitable paired inference for zero-discordance differences; state observed zero errors separately from the bound.

5. **major - Documentation drift guard accepts a materially false, already-listed number.** `eval/numbers.py:29-53`, `eval/check_docs.py:48-72`, `thought_node.md:93`. `allowed()` pools rounded numbers from every working-tree result, regardless of claim or document, and the required-claim check only looks for a string anywhere in a slice. I deliberately changed the selection memo's synthetic cost from **`$7.32 -> $3.66`** to **`$7.32 -> $7.32`**; `check_docs` still printed `OK (0 problems)`. I restored the edit. It also reads working-tree JSON rather than verifying committed inputs. **Fix:** bind numeric placeholders or anchored claims to their particular result fields, compare generated deliverables against freshly rendered templates, verify the source revision, and add this false-negative as a test.

6. **major - Missing offline responses become valid-looking completed runs.** `eval/run_llm_gaps.py:161-174,269-283`, `eval/run_prob_pack.py:66-79`. A missing `(model, item_id, prompt hash)` produces an empty response instead of stopping. On real negatives this scores as `NONE` and can suppress measured false claims; tracing substitutes 0.5 probabilities. The run still writes a scored JSON and exits successfully (though it records an error/invalid count). All requested current stores were complete, so this did **not** cause today's matching scores. **Fix:** in offline mode, validate the expected keys and response/configuration fingerprints up front and raise on any missing record; retain the registered invalid-response scoring only for an actual stored response.

7. **major - Tracing retains a known, undisclosed rule-composition ambiguity.** `components/bugs/school_math.py:164-168`, `eval/run_llm_gaps.py:427,525-555`. When a learner holds both `SQ_DOUBLE` and `NEG_TIMES_NEG`, the interpreter silently gives `SQ_DOUBLE` priority on a squared negative; the LLM's five-rule prompt does not specify that priority. Inversion explicitly excludes this pair on a negative square, but tracing does not: **9/100** simulated learners hold both and **7/100** encounter a displayed negative square. The two-point tracer-versus-GPT-5.4-mini difference is small enough that these ambiguous observations warrant a sensitivity analysis. **Fix:** specify the composition precedence in the prompt, or remove/stratify conflicting items and rerun the paired tracing metrics.

8. **minor - Retries are incompletely accounted for and malformed nonempty replies are not retried.** `eval/run_llm_gaps.py:173-199`, `eval/run_prob_pack.py:78-92`. The loop stops on any nonblank text, before checking whether its JSON/schema is valid, contrary to the protocol's "invalid or empty" retry rule. Only the final attempt's usage is stored and `usage_summary.calls` counts one row, not actual API requests. The committed files show **13 extra GPT-5.4-mini inversion calls and one tracing call** (`attempts=2`) that the call and spend totals omit; the sole final invalid inversion response was empty after two attempts. **Fix:** validate the part-specific output before stopping; retain usage, status and latency for *each* attempt and bill/count all calls.

9. **minor - The real-data parser commits to the first evaluable math segment even when its key is wrong.** `components/bugs/eedi_parse.py:39-52`, `eval/run_llm_gaps.py:203-220`. In the fetched 4,370-row mirror, **22** questions have a first parsed segment disagreeing with Eedi's correct answer but a later segment agreeing (one linked-positive, 21 other-labelled). The current return prevents those later candidates from being considered, affecting coverage and which other-labelled items qualify as negatives. Not every later matching segment is necessarily the intended question, so switching selection without checking context would also be unsafe. **Fix:** disambiguate the relevant segment against the answer and question wording, quantify changes in P/N/S and FCR, and register the parsing sensitivity rather than silently replacing this sample.

10. **minor - The on-disk LLM cache crosses endpoints/model revisions.** `components/llm.py:66-99,127-132`. Its key hashes backend and request body but omits Azure endpoint, API version and deployed model revision. With mocked HTTP, changing between two endpoints returned the first endpoint's cached result without a second request. A separate mocked canary test confirmed the credential/header is **not** written into the cache and that the reasoning branch sends `max_completion_tokens` and `reasoning_effort` without `temperature`/`seed`. **Fix:** include nonsecret endpoint/API-version/revision identifiers in cache and saved-response provenance; keep authorization headers and keys out of both.

11. **minor - External evaluation inputs are not pinned.** `eval/data/fetch.py:25-38`. Every source uses Hugging Face `resolve/main`, and an existing `.data/` file is accepted without checksum verification. Today's downloaded files reproduce the results, but a revised mirror can change the item population or names without a code diff; fidelity to the official Kaggle data is already disclosed as unverified. **Fix:** pin immutable HF revisions, record SHA-256 and row/schema checks, and reject stale local files.

12. **minor - Engine determinism is asserted rather than measured in the consistency task.** `eval/run_cascade.py:75-82`. The comment says "recompute twice", but the loop calls `executable_match` once per item and then unconditionally writes `"deterministic": true`. This does not affect the requested offline cascade output, but it is not evidence for the repeated-run claim. **Fix:** run each fixed item at least twice, compare parsed outputs, and report the observed agreement.

## 3. Verdict

**The conditional sample scores are reproducible, but the headline safety and cascade-savings claims are not established as stated.** Real P/N grouping, `S_equiv` (two included positives), `S_related` (21 sensitivity items), FCR, balanced accuracy, claim precision, six-label macro-F1, inversion minimal-set filtering, and paired/stratified bootstrap indexing matched inspection and independent checks. The five probability formulas match their stated local rules; tracing Brier, exact-set and macro-F1 implement their stated definitions. Real classification, inversion, tracing and probability-diagnosis prompts contain the problem and answer, not the gold misconception or held set; probability *generation* intentionally supplies the target description as an input. The synthetic diagnosis *engine* does read its generator-known target. The real prompt has more original question context than the exact parser, while the synthetic engine has hidden executable/provenance information.

The protocol's stated registration minutes match `git log -p` commit times: main protocol `63e7694` at **15:21:42 IST**, Addendum A `ce0f3a2` at **15:29:54**, and Addendum B `654968c` at **15:51:52**. Those commits establish registration times, not independent proof of when external calls began. The strongest LLM had **zero observed** false claims on 152 selected negatives, not a demonstrated zero population risk. The 50% synthetic call saving follows the chosen 50/50 item mix; the actual routed-token costs contradict the reported 50% *money* saving. Treat the current JSON as an auditable re-score of this mirror and these stored responses, not as independent evidence of a safe, cheaper general tutor until issues 1-5 are addressed.
