# R1B papers novelty — Perceptron P08 misconception tutor

Access date: 2026-10-04 IST. Scope: newest-first 2024–2026, with classics only where opened sources could be verified. All cited claims below are from sources opened in this session.

## TL;DR (cited bullets)

- **Direct Eedi/Kaggle-style misconception matching is now real but mostly retrieval/rerank, not executable bug synthesis.** Eedi’s first-party writeup frames the task as predicting which misconception descriptions match a distractor, including unseen misconceptions; the winning system used Qwen retrieval/rerank, LoRA/contrastive learning on **10k synthetic + 1.8k real examples**, and Claude-generated rationales for reranking (https://www.eedi.com/news/from-wrong-answers-to-real-insights-how-we-used-a-kaggle-challenge-to-map-student-misconceptions, accessed 2026-10-04).
- **Lan/Eedi-adjacent 2024 work shows LLMs struggle to anticipate real student distractors unless trained/ranked against student data.** DiVERT reports a **1,434-question** real-world math MCQ dataset used by **hundreds of thousands of students**, and says a **7B** open-source LLM approach outperformed GPT-4o-based state of the art on downstream distractor generation (https://arxiv.org/abs/2406.19356, accessed 2026-10-04).
- **Executable misconception modeling is no longer wholly novel in 2026.** MalruleLib explicitly translates documented misconceptions into executable procedures, encodes **101 malrules** over **498 parameterized problem templates**, can generate **over one million instances**, and defines Malrule Reasoning Accuracy; LLM accuracy drops from **66%** direct solving to **40%** cross-template misconception prediction, while traces improve prediction by **3–15%** (https://aclanthology.org/2026.acl-long.690/, accessed 2026-10-04).
- **Our spike can still claim a sharper Eedi-distractor validation + item-generation angle** if we actually compile natural-language misconceptions into executable programs and validate them by reproducing labelled real distractor choices, then use those programs to choose discriminative parameters with SymPy-verified keys. Opened sources did not show this exact closed loop.
- **Calibration/abstention evidence is thin for misconception diagnosis specifically.** Opened arXiv searches found zero results for `uncertainty` + `knowledge tracing` + `LLM`; related 2026 education work discusses abstention/confidence scoring or explicit abstention in deterministic didactic pipelines, but not slip-vs-systematic misconception classification for Eedi-style distractor diagnosis (arXiv API searches accessed 2026-10-04).

## Findings per item

### 1. LLM-based misconception identification/diagnosis from wrong answers or explanations

- **Eedi production/competition context.** Eedi says its diagnostic MCQ distractors are crafted to reveal specific misconceptions, but it lacked labels linking distractors to misconceptions; manual tagging was “Painful. Slow. Inconsistent. Not scalable.” The Kaggle task was: given a distractor and a list of misconception descriptions, predict matching misconceptions; many test misconceptions were unseen (https://www.eedi.com/news/from-wrong-answers-to-real-insights-how-we-used-a-kaggle-challenge-to-map-student-misconceptions, accessed 2026-10-04). Eedi’s data page lists **7 individual sets** and defines a misconception as a flawed conceptual structure/gap that produces a systematic, predictable error pattern (https://www.eedi.com/data-and-competitions, accessed 2026-10-04).
- **Benchmark for algebra misconceptions.** Otero, Druga, and Lan introduce a middle-school algebra benchmark with **55 misconceptions/common errors** and **220 diagnostic examples** from prior peer-reviewed studies; their LLM example reaches **83.9% precision/recall** when educator feedback is included and testing is topic-restricted. They report feedback from **5** middle-school math educators: **80% or more** encountered these misconceptions, and **4/5** were interested in using the dataset with AI (https://arxiv.org/abs/2412.03765, accessed 2026-10-04).
- **DiVERT / Eedi-affiliated UMass line.** Fernandez, Scarlatos, Feng, Woodhead, and Lan introduce DiVERT, a variational method learning text representations of errors behind distractors. Opened abstract claims a real-world math MCQ dataset of **1,434 questions** used by **hundreds of thousands of students**, and that a **7B** open-source LLM outperforms GPT-4o-based state-of-the-art approaches for downstream distractor generation; educator evaluation found error labels comparable to human-authored ones (https://arxiv.org/abs/2406.19356, accessed 2026-10-04).
- **Other 2024 UMass/Lan distractor work.** Opened arXiv API entries show: (a) human–LLM math MCQ generation found LLM stems promising but distractors that capture common student errors/misconceptions limited (https://arxiv.org/abs/2405.00864, accessed via arXiv API 2026-10-04); (b) overgenerate-and-rank trains a ranking model to predict how likely real students are to select generated distractors and increases alignment with human-authored distractors, though human-authored remain preferred (https://arxiv.org/abs/2405.05144, accessed via arXiv API 2026-10-04); (c) broader LLM distractor-generation experiments find LLMs can make mathematically valid distractors but are less adept at anticipating common errors or misconceptions among real students (https://arxiv.org/abs/2404.02124, accessed via arXiv API 2026-10-04).
- **Dialogue knowledge tracing.** Scarlatos, Baker, and Lan use LLMs to identify knowledge components/skills and correctness in tutor-student dialogue turns, verify with human expert annotations, and apply KT across dialogues; the abstract says LLMKT significantly outperforms existing KT methods on two tutoring dialogue datasets, but no exact opened numeric results (https://arxiv.org/abs/2409.16490, accessed 2026-10-04).
- **Feedback generation.** Scarlatos et al. propose a rubric for math feedback validity and train Llama 2 with DPO using GPT-4 annotations; the abstract claims significant increases in correctness and alignment for generated feedback, but no exact opened numbers (https://arxiv.org/abs/2403.01304, accessed via arXiv API 2026-10-04).

### 2. Novelty check: executable misconceptions / bug programs

- **Modern executable-malrule overlap is strong.** MalruleLib (Chen, Liu, Sonkar, ACL 2026) is the closest opened prior art: it “translates documented misconceptions into executable procedures,” draws on **67** learning-science/math-education sources, produces step-by-step malrule-consistent traces, defines MRA (infer a misconception from one worked mistake and predict next answer under cross-template rephrasing), encodes **101 malrules** over **498** parameterized templates, generates **over one million instances**, and reports cross-template degradations of **10–21%** plus trace gains of **3–15%**. This directly weakens any claim that “executable misconceptions” alone are novel (https://aclanthology.org/2026.acl-long.690/, accessed 2026-10-04).
- **MalAlgoPy is adjacent but model-centric.** Sonkar et al. introduce MalAlgoPy, a Python library generating datasets of authentic student solution patterns through graph-based algebraic problem-solving, then instruction-tune LLM Cognitive Student Models. The opened abstract/page says misconception training replicates errors but hurts correct solving where misconceptions do not apply; calibrating the correct-to-misconception example ratio, sometimes **0.25**, can satisfy both properties. This is simulation/training-data generation, not opened evidence of compiling arbitrary misconception text to validated programs against Eedi distractors (https://arxiv.org/abs/2410.12294; https://scale.stanford.edu/ai/repository/llm-based-cognitive-models-students-misconceptions, accessed 2026-10-04). GitHub repository search for `MalAlgoPy` returned `total_count:0` (https://api.github.com/search/repositories?q=MalAlgoPy&per_page=10, accessed 2026-10-04).
- **Classical malrule tradition exists.** Sleeman’s ERIC record for “Mis-generalization: An Explanation of Observed Mal-rules” says the Leeds Modelling System used a database of correct/incorrect mal-rules sufficient to diagnose many difficulties for 15-year-olds, but failed on many errors from **24** 14-year-old students; it distinguishes manipulative mal-rules from parsing errors and says bug migration can be explained by repair theory, while parsing errors are better explained by mis-generalization (https://eric.ed.gov/?id=ED258845, accessed 2026-10-04). Opened source confirms the malrule/database diagnosis tradition, but not Brown/Burton details directly.
- **What was not found in opened sources.** I did not find/open a 2024–2026 source showing an LLM that takes natural-language misconception descriptions from an Eedi-style graph, synthesizes executable bug programs over parameterized problem families, automatically validates each program by reproducing labelled real distractor answers, then uses those validated programs for pairwise-discriminative item generation with symbolic answer verification.

### 3. Programming-misconception diagnosis with LLMs (2023–2026)

- **Code explanation diagnosis.** Oli, Banjade, Olney, and Rus study LLMs for identifying gaps and misconceptions in students’ self-explanations of code examples. The opened arXiv abstract compares zero-shot prompting, supervised fine-tuning, and ORPO preference alignment; GPT-4 consistently outperformed LLaMA3 and Mistral in human evaluations, fine-tuned models beat zero/few-shot prompting for gaps, and ORPO outperformed SFT for identifying gaps/misconceptions. No exact opened numeric metrics (https://arxiv.org/abs/2501.10365, accessed 2026-10-04).
- **Prototype app.** A public GitHub repository describes a “Prototype web application for LLM-based detection of programming misconceptions in novice student code written in Processing, a Java-based programming language”; metadata opened: TypeScript, **0 stars**, **0 forks**, pushed **2026-06-12**, license `NOASSERTION` (https://api.github.com/repos/KlTobias/MisconceptionDetection, accessed 2026-10-04). Maturity: prototype code.
- **Other programming sources remain unverified.** Search surfaced ICSE-SEET 2024 and EACL 2026 items, but accessible primary pages did not expose enough content in opened sources, so claims/numbers stay in UNVERIFIED.

### 4. Calibration / abstention: slip vs systematic misconception

- **No targeted opened hit for LLM misconception-diagnosis calibration.** An arXiv API query for `uncertainty` + `knowledge tracing` + `LLM` returned **0** results (https://export.arxiv.org/api/query?search_query=all:%22uncertainty%22%20AND%20all:%22knowledge%20tracing%22%20AND%20all:%22LLM%22&sortBy=submittedDate&sortOrder=descending&max_results=15, accessed 2026-10-04).
- **Adjacent MCQA evaluation.** “Check The Scoreboard” (EMNLP 2026) studies education-inspired MCQA scoring schemes including distractor elimination, abstention, confidence calibration, and self-correction; it reports these schemes shift rankings of **31 LLMs**, better predict LLM Arena preferences, and reveal distinct capabilities, e.g. GPT-5 rarely abstains while weaker open-weight models often abstain (https://export.arxiv.org/api/query?search_query=all:%22abstention%22%20AND%20all:%22education%22%20AND%20all:%22LLM%22&sortBy=submittedDate&sortOrder=descending&max_results=15, accessed 2026-10-04). This is not misconception diagnosis.
- **Adjacent deterministic abstention.** A didactical-driven teacher assistant for dimensional modeling evaluates **195** authentic student questions and reports high pair precision (**73%**) with full traceability and explicit abstention; again, this is intent/concept/didactic routing, not math misconception slip-vs-systematic classification (same arXiv API URL above, accessed 2026-10-04).

## Novelty verdict for our spike (what we can and cannot claim)

### We can claim, if implemented and evaluated

1. **Eedi-distractor-grounded validation loop.** Opened prior art supports retrieval/rerank misconception matching and executable malrule libraries separately, but I did not open a source that validates LLM-compiled bug programs by reproducing labelled Eedi distractor answers.
2. **Natural-language misconception → executable bug compiler for a contest prototype.** This is narrower than “executable misconceptions” because MalruleLib already translates documented misconceptions into executable procedures; the defensible claim is the compiler+validation workflow over external natural-language misconception descriptions and real distractor labels.
3. **Discriminative item generation from validated bug programs.** MalruleLib generates instances and traces at scale, but opened text does not say it chooses parameters so competing bug programs yield pairwise-distinct wrong answers with SymPy-verified answer keys. This remains a plausible differentiator.
4. **Hybrid diagnosis: executable likelihood fused with LLM retrieval/rerank.** Eedi winner-style pipelines are retrieval/rerank; executable bug likelihood can be positioned as a mechanistic feature/source of evidence rather than a replacement.

### We cannot claim

1. **“First executable misconception system.”** False/unsafe after MalruleLib and classical malrule systems.
2. **“LLMs have not been used to simulate misconceptions.”** False/unsafe after MalAlgoPy/CSM.
3. **“Misconception-aware distractor generation is unsolved from scratch.”** Too broad: DiVERT and UMass/Lan distractor papers directly address error-aware distractor generation.
4. **Exact superiority numbers for our approach.** No experiments run here; any MAP@25, reproduction-rate, calibration, or learning-gain claims must await implementation/evaluation.
